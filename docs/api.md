# Engine API reference

Generated by `fengine --write-api` from the C++ bindings. These are the
services the engine provides; game logic lives in Lua (see `lualib/fe` and docs/scripting.md).

## Conventions

- **Angles are degrees** everywhere: camera yaw, pitch and fov, `entity.yaw`, `world:spawn{yaw}`, canvas `rotation`, light cones and backdrop yaw.
- **World positions, directions and grid cells are tables**, as arguments and results: positions `{x, y, z}` (x and z required; y is optional where an entity is put on the ground), ground-plane vectors `{x, z}`, grid cells `{x, z, layer}` with integer, 0-based coordinates (cell x covers world x..x+1; layer defaults to 0). Lists returned to Lua are 1-based.
- **Canvas positions and sizes are plain numbers** (`fe.canvas.rect(x, y, w, h)`, `fe.input.mouse()` returns `x, y`, `camera:project` returns `x, y, visible`); a rectangle inside an options table, or an optional one, is a `Rect` table.
- **Multiple results** are used for sizes and canvas positions (`w, h`, `x, y`) and for a few pairs of related values (`fe.save.read`: data, meta; `world:pick`: cell, point; `camera:ray`: origin, direction); everything else returns one value or one table.
- **Getters are nouns and setters `set_<noun>`** (`fe.app.title()` / `fe.app.set_title()`, `fe.audio.bus_volume()` / `fe.audio.set_bus_volume()`, `world:cell()` / `world:set_cell()`). Plain values of handles are properties (`camera.yaw`, `entity.yaw`, `world.paused`); read-only ones are marked. Vector properties return a copy: assign a whole table (`camera.target = {x = 1, y = 0, z = 2}`); `camera.target.x = 1` changes nothing.
- **Entity components** (`sprite`, `mesh`, `mover`, `light`, `emitter`, `collider`, `audio`, `platform`) follow one rule: `e:light{...}` adds the component or changes it and returns its new state as a table, `e:light()` with no argument reads that table (nil when the entity has no light; nothing is added, so `e:light{}` adds one with its defaults), and an explicit nil, `e:light(nil)`, removes it.
- **Options tables** carry the optional settings of a call (`world:overlay_path(name, cells, {color = ...})`), after its required arguments. Every table a binding reads (options, settings, vectors, colours, cells, lists) is read raw: no metamethod runs, so fields must be in the table itself (one inherited through `__index` is not seen).
- **Invalid input raises a Lua error**: arguments and option fields of the wrong type, unknown names (enums, input actions and axes), fractions where an integer is expected, integers outside the range the engine stores them in (`bad argument #3 to 'fe.text.paginate' (integer from -2147483648 to 2147483647 expected, got the number 9223372036854775807)`), NaN or infinite numbers and numbers beyond the float range (about 3.4e38), vectors without their components, colours that are not colours, paths containing a NUL character, and values outside a documented range. Leaving an optional value out (nil) uses its default. A few camera and canvas values are held within their range instead (camera pitch, canvas alpha), as noted. An argument of the wrong type raises `bad argument #n to 'World:spawn' (World expected, got Entity)`, naming the documented types.
- **The world bound**: every component of a position, vector, rectangle or colour table is within -1000000 to 1000000. Sizes, counts and speeds have documented ranges (collider radius 0 to 64, mover speed 0 to 1000, light radius at most 1000, overlays of at most 65536 cells, emitter `max` 1 to 16384...), so no single call can make the engine loop or allocate without end.

## Types

| Name | Type | Description |
| --- | --- | --- |
| `Vec3` | `{x: number, y?: number, z: number}` | A world position or vector; `{1, 2, 3}` also works. Positions need x and z; offsets and directions may leave components out (0). Components are within -1000000 to 1000000. |
| `Cell` | `{x: integer, z: integer, layer?: integer}` | A grid cell: 0-based integer coordinates, layer 0 by default. `{x, z, layer}` positionally also works; cell tables the engine returns carry more fields, which are ignored. |
| `Rect` | `{x: number, y: number, w: number, h: number}` | A rectangle in canvas or image pixels; `{x, y, w, h}` positionally also works. |
| `Color` | `integer/string/{r: number, g: number, b: number, a?: number}/number[]` | 0xRRGGBBAA, a color name or '#rrggbb[aa]', or 0..1 components (above 1 is HDR where supported). A plain number is always 0xRRGGBBAA, so 0.5 is an error. |
| `TextOptions` | `{font?: string, size?: number, color?: Color, width?: number, align?: 'left'/'center'/'right', visible?: integer, shadow?: Color, outline?: Color, line_gap?: number}` | Text layout and style: `size` is 0 to 1024 (0 = the font's own), `width` (0 to 1000000) wraps (0 = no wrapping), `visible` reveals that many units (typewriter). |

## `fe.json`

JSON conversion. A non-empty sequence (keys 1..n, nothing else) becomes an array and any other table an object. Object keys carry the Lua key's type: an integer key k is written "#k" and a string key that starts with '#' gets a second '#', so {[1] = 'a', ['1'] = 'b', ['#t'] = 'c'} encodes as {"#1": "a", "1": "b", "##t": "c"} and decodes back to the same table; other keys and keys like "#x" or "#01" stay strings. Values nest at most 128 levels; deeper ones raise an error, as do functions, userdata, non-integer number keys and NaN or infinite numbers. fe.save uses the same conversion.

| Name | Type | Description |
| --- | --- | --- |
| `decode` | `fun(text: string): any` | Parse JSON text ("#k" keys become integer keys, see above). |
| `encode` | `fun(value: any, pretty?: boolean): string` | Serialize a value (tables, strings, numbers, booleans); integer keys of non-sequence tables are written "#k". |
| `read` | `fun(path: string): any` | Read and parse a JSON file inside the game folder ('@fe/' for lualib). |

## `fe.save`

Per-user persistence. Saves are JSON documents the game defines; the engine adds no schema.

| Name | Type | Description |
| --- | --- | --- |
| `write` | `fun(slot: string, data: table, meta?: table)` | Atomically write a save slot, keeping the previous version as its .bak. Raises (writing nothing) for data that could not be read back: tables nested deeper than 127 levels (the save file wraps them in one more) and the values fe.json.encode rejects. |
| `read` | `fun(slot: string): table?, table?, true?` | Read a slot's data and metadata (nil when empty). When the slot's file is missing or cut short (an interrupted write) the previous save kept as its .bak is read instead, a warning is logged and the third result is true. A slot file that is complete but unreadable (invalid JSON, nested too deep, not a save) raises an error instead of loading the previous save. |
| `list` | `fun(): {slot: string, meta: table, modified: number, thumbnail: boolean, backup?: true}[]` | All saved slots. `backup` marks a slot whose file is missing or cut short, listed (and read) from its previous version; an unreadable slot has meta = {corrupt = true}. |
| `delete` | `fun(slot: string)` | Delete a slot, with its thumbnail and blobs. |
| `write_blob` | `fun(slot: string, name: string, bytes: string)` | Store bytes (any string, binary included) next to a slot under `name` (slot naming rules), through the save backend: world snapshots for a new game plus, replay inputs, anything that is not JSON. At most 16 MiB; the slot need not exist yet. Deleting the slot deletes its blobs. |
| `read_blob` | `fun(slot: string, name: string): string?` | A slot's blob, or nil when there is none. |
| `remove_blob` | `fun(slot: string, name: string)` | Delete one of a slot's blobs. |
| `blobs` | `fun(slot: string): string[]` | Names of a slot's blobs, sorted. |
| `thumbnail` | `fun(slot: string)` | Capture the next frame's 3D scenes (no canvas UI, screen effects or editor) as the slot's thumbnail. |
| `thumbnail_path` | `fun(slot: string): string?` | The slot's thumbnail as a 'user://thumbnails/<slot>.png' path for fe.canvas.image (nil when there is none). |
| `read_config` | `fun(): table` | Read the player's settings file. |
| `write_config` | `fun(settings: table)` | Write the player's settings file. |

## `fe.input`

Action-mapped input. Raw inputs are named 'key:<scancode name>' ('key:Z', 'key:Return'), 'mouse:left', 'mouse:right', 'mouse:middle', 'mouse:x1', 'mouse:x2', 'pad:<control>' for any gamepad ('pad:a', 'pad:leftx') and 'pad1:<control>', 'pad2:<control>'... for one gamepad, numbered from 1 in connection order. Analog inputs take '+' or '-' for one direction ('pad:leftx+'). The engine has no default bindings; scripts define every action. Text entry, gamepad descriptions and rumble are here too.

| Name | Type | Description |
| --- | --- | --- |
| `define` | `fun(action: string, inputs: string[], threshold?: number)` | Define or replace an action. |
| `define_axis` | `fun(name: string, spec: {negative?: string[], positive?: string[], analog?: string[], deadzone?: number})` | Define an axis from digital and analog raw inputs. |
| `clear` | `fun()` | Remove all actions and axes. |
| `bind` | `fun(action: string, inputs: string[])` | Rebind an action. |
| `bindings` | `fun(action: string): string[]` | Current inputs of an action. |
| `pressed` | `fun(action: string): boolean` | Went down this tick. |
| `held` | `fun(action: string): boolean` | Currently down. |
| `released` | `fun(action: string): boolean` | Went up this tick. |
| `repeating` | `fun(action: string, delay?: number, interval?: number): boolean` | Pressed, then repeats while held (menu navigation). |
| `held_time` | `fun(action: string): number` | Seconds the action has been held. |
| `axis` | `fun(axis: string): number` | Axis value -1..1. |
| `raw` | `fun(input: string): number` | Raw input value. |
| `pressed_inputs` | `fun(): string[]` | Raw inputs that went down this tick (for rebinding screens). Stick axes are left out. |
| `last_device` | `fun(): string` | 'keyboard', 'gamepad' or 'mouse': the kind of device used last. |
| `device_type` | `fun(pad?: integer): 'keyboard'/'xbox'/'playstation'/'switch'/'steamdeck'/'generic'/nil` | Button layout for prompts: 'keyboard' while the keyboard or mouse was used last, otherwise the layout of the gamepad used last. With a gamepad number, that gamepad's layout (nil when it is not connected). |
| `device_name` | `fun(pad?: integer): string?` | Model name of the gamepad used last, or of gamepad `pad` (nil when it is not connected). |
| `pads` | `fun(): {number: integer, name: string, type: string, rumble: boolean, trigger_rumble: boolean}[]` | Connected gamepads by number, with their layout and whether they can rumble. |
| `rumble` | `fun(low: number, high: number, seconds: number, pad?: integer)` | Vibrate the low- and high-frequency motors (0..1) for up to 60 seconds; a new call replaces the previous one. Without a gamepad number, every gamepad. 0, 0 stops. |

| `text_begin` | `fun(rect?: Rect, kind?: 'text'/'name'/'number')` | Start text entry: typed text arrives through fe.input.text, the IME places its candidate window near `rect` (canvas pixels, the field being edited) and an on-screen keyboard opens where the system has one (Steam Deck, touch screens). Keys still report as raw inputs. Calling it again moves the area. |
| `text_end` | `fun()` | Stop text entry and close the IME or on-screen keyboard. |
| `text_active` | `fun(): boolean` | Text entry is on. |
| `text` | `fun(): string` | UTF-8 text committed this tick (typed characters, or an IME's finished composition). |
| `composition` | `fun(): string, integer` | The IME's unfinished text and the cursor position in it (in characters); '' when none. Draw it after the committed text. |
| `mouse` | `fun(): number, number` | Mouse position in canvas pixels. |
| `mouse_moved` | `fun(): boolean` | Mouse moved this tick. |
| `wheel` | `fun(): number` | Wheel movement this tick. |
| `feed` | `fun(input: string, value: number)` | Inject a raw input; it applies on the next tick. Only in development builds, --test/--check runs and --replay/--record sessions. |

## `fe.text`

Fonts, colors, icons and markup. Markup tags: {color:x} {icon:id} {wait:s} {speed:cps} ({speed:0} = the rest at once) {size:scale}...{/size} {b}...{/b} {shake}...{/shake} {wave}...{/wave} {ruby:base|reading}; other {tags} are passed to the resolver set with fe.text.resolver. Lines break at spaces and between CJK characters (kinsoku rules); right-to-left scripts are not supported.

| Name | Type | Description |
| --- | --- | --- |
| `font` | `fun(name: string, spec: {files: string[], size?: number, pixel?: boolean, bold?: {files: string[], size?: number, pixel?: boolean}})` | Define a font: .fnt bitmap fonts and/or .ttf/.otf faces, first match wins per character. `bold` defines the {b} face (the font '<name>.bold'); without one, bold text is drawn twice, 1px apart. |
| `color` | `fun(name: string, color: Color)` | Name a color for {color:name}. |
| `icon` | `fun(id: string, spec: {image: string, rect?: Rect})` | Register an {icon:id} image. |
| `resolver` | `fun(resolver: (fun(tag: string): string?)/nil)` | Resolve custom tags such as {player} or {var:name}; nil removes the resolver. It runs under a C call (from fe.text, fe.canvas.text and the frame's text layout) and must not yield: a task.wait in it raises 'attempt to yield across a C-call boundary'. A resolver may replace or remove itself; the call in progress finishes with the old one. Its errors are reported and the tag is shown as written. A resolver that resolves markup with tags through fe.text or fe.canvas.text nests: more than 8 nested resolver calls raise one error from the outermost fe.text or fe.canvas.text call, as does the watchdog stopping a resolver. Tags in a replacement resolve too, up to 4 levels deep; replacements totalling more than 1 MiB (1048576 bytes) for one call raise an error. |
| `units` | `fun(markup: string): {count: integer, wait: table<integer, number>, speed: table<integer, number>}` | Reveal units for typewriter effects. `speed[i]` is the reveal speed from unit i on (0 = show the rest at once); ruby readings appear with their base. |
| `measure` | `fun(markup: string, options?: TextOptions): number, number, integer` | Width, height and line count. |
| `paginate` | `fun(markup: string, options: TextOptions, lines: integer): string[]` | Split text into pages that fit `lines` wrapped lines of `options.width`. |
| `plain` | `fun(markup: string): string` | Markup with tags removed. |

## `fe.audio`

Music layers with loop points, crossfades, seeking and pitch; sounds and voices; buses with volume, low-pass, reverb and ducking; positional sounds heard from a world's camera.

| Name | Type | Description |
| --- | --- | --- |
| `music` | `fun(path: string, options?: {layer?: string, fade?: number, loop_start?: number, loop_end?: number, volume?: number, pitch?: number, preserve_speed?: boolean, loop?: boolean, sync?: boolean})` | Play music on a layer, crossfading from what was there. `sync` starts a stem at the main layer's position, sample-aligned. `pitch` (0.25-4) changes speed and pitch together, or with `preserve_speed` the pitch alone (the track keeps its duration; outside 0.5-2 it falls back to changing both); `volume` is 0 to 4. |
| `stop_music` | `fun(layer?: string, fade?: number)` | Fade out one layer, or all music. |
| `music_volume` | `fun(layer?: string): number` | Volume of a music layer (default 'main'). |
| `set_music_volume` | `fun(layer: string, volume: number, fade?: number)` | Mix a music layer (stems), 0 to 4. |
| `music_pitch` | `fun(layer?: string): number` | Speed and pitch of a music layer (default 'main'). |
| `set_music_pitch` | `fun(layer: string, pitch: number, options?: {preserve_speed?: boolean})` | Speed and pitch of a layer, 0.25 to 4 (1 = normal); setting 'main' also sets its synced stems. | `:cursor` | `fun(cell: Cell/nil, options?: {color?: Color})` | Show the grid cursor on a cell; nil hides it. The colour is kept until an options table changes it. |
| `:burst` | `fun(position: Vec3, settings: table, count?: integer)` | One-shot particle burst (up to 4096). |

## `fe.world`

Load and manage worlds (maps). Several can be loaded at once.

| Name | Type | Description |
| --- | --- | --- |
| `load` | `fun(name: string, map: string): World` | Load maps/<map>/map.json as a world called `name` (replacing one of that name). |
| `get` | `fun(name: string): World?` | A loaded world by name. |
| `unload` | `fun(name: string)` | Unload a world. |
| `list` | `fun(): string[]` | Names of loaded worlds. |
| `load_async` | `fun(name: string, map: string): integer` | Start loading maps/<map>/map.json in the background: the map file is parsed and the models, images and sprites it names are decoded on worker threads. Returns a ticket for load_progress and finish_load. |
| `load_progress` | `fun(ticket: integer): number` | Background load progress 0..1; 1 when finish_load won't wait (or the load failed). |
| `finish_load` | `fun(ticket: integer): World` | Create the world from a background load, replacing a world of that name. Before progress reaches 1 it waits for the map file and leaves undecoded assets to load on first use. Raises the load's error (a missing or invalid map). The ticket is used up. |
| `cancel_load` | `fun(ticket: integer)` | Drop a background load that will not be finished (a cancelled warp): the ticket stops advancing and becomes unknown; a worker still parsing the map finishes in the background and its result is discarded, and assets already decoded stay in the cache like any other. |

## `fe.platform`

Storefront services: unlockable milestones and stats. A port or game module can supply a store backend (Steam, a console SDK); the default keeps them in the user-data folder (platform.json).

| Name | Type | Description |
| --- | --- | --- |
| `name` | `fun(): string` | The backend: 'local' (user-data folder) or the store a port plugged in. |
| `unlock` | `fun(id: string)` | Unlock a milestone by its store id; unlocking twice does nothing. |
| `unlocked` | `fun(id: string): boolean` | Whether a milestone is unlocked. |
| `set_stat` | `fun(name: string, value: number)` | Set a stat by its store name. |
| `stat` | `fun(name: string): number?` | A stat's value, nil when never set. |

## `fe.harness`

Test-only controls. They exist only while `fengine_headless --test` runs a game's tests; games never see them.

| Name | Type | Description |
| --- | --- | --- |
| `start` | `fun(): boolean` | Load and initialise the entry module. |
| `tick` | `fun(ticks?: integer)` | Advance the engine by fixed ticks (default 1, at most 36000), drawing each one. |
| `errors` | `fun(): integer` | Recorded script errors. |
| `begin_test` | `fun()` | Restart the script watchdog's clock. fe.test calls it before each test, so every test (like every tick) gets the whole watchdog limit. |
| `reload` | `fun(target: string): boolean` | Hot-reload a loaded module, named as for require or by its Lua file ('@fe/...' for lualib), as a file change does in development builds; false when no loaded module comes from it. |
