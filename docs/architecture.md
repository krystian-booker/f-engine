# Architecture

```
game folder      main.lua · data/*.json · maps/ · sprites/ · audio/ · any Lua modules   (owned by the game)
     │ require: the game folder is searched first, so a game overrides any kit module
lualib/fe/       scene · task · signal · tween · state · save · schema · data · test
                 field · event · cutscene · dialogue · ui · rpg · effects · battle · tactical · ...
     │ sol2 bindings (fe.*), described by generated docs/api.md and lualib/types/fengine.d.lua
engine/          platform · input · assets · world · nav · render · canvas · text · audio · saves
                 Lua host · hot reload · editor · replays                         (C++ services only)
```

## The boundary rule

If a concept would appear in a JRPG design document, it does not belong in `engine/` C++. The engine knows about entities, sprites, meshes, lights, grids, paths, reachability, raycasts, text, sounds and files. It does not know about HP, parties, items, skills, battles, turns, shops, encounters or quests. `tools/ci/check_boundary.py` scans `engine/` for that vocabulary and is a CTest test.

## Libraries and programs

| Target | Contents |
| --- | --- |
| `fengine_core` | Headless: `core` (paths, JSON, asset cache, log, random), `assets` (images, glTF models, sprite animations), `text`, `nav`, `world`, `services` (input state, canvas command list, screen effects, audio interface, saves, platform services), `script` (Lua host and bindings), `runtime` (`Engine`, the background `WorldLoader`, `EmitterAudio`, `ReplayHarness` and the headless runner) |
| `fengine_runtime` | SDL3 window and input, miniaudio, bgfx renderers (world, canvas, ImGui), the editor and `MainLoop` |
| `fengine` | The player and development runtime |
| `fengine_headless` | `--test`, `--check` and `--write-api`; needs no GPU or display |

Game files are read through `engine/core/Paths.h`. A folder may ship as a `.pak` archive (`engine/core/Pack.h`: an index of names, sizes and CRC-32s, with each entry stored or zlib-compressed); `<dir>/game.pak` stands in for `<dir>/game` and `lualib.pak` for `lualib`. Mounting an archive lays its entries over the folder: `require`, `fe.fs`, `fe.json.read`, maps, images, sprites, fonts, glTF models, LUTs, cooked `.ktx` textures and compiled game shaders (`shaders/<backend>/*.bin`) read them in memory, and audio, which miniaudio opens by file name, is extracted on first play into a private temporary folder that is removed at exit. Where a loose file and an entry share a path, development builds read the loose file and ship builds the entry. Archive entry names are validated relative paths, and every path a script names still goes through `resolveInside`, so archives are sandboxed like folders. The asset cache also reads `user://` images (save thumbnails) from the user-data folder, read only.

Services in the core are plain data. For example, the canvas records quads and the world stores entities, lights and overlays. The runtime's renderers consume that data, so all game logic, including UI, runs and is tested headless.

The asset cache (`engine/core/AssetCache.h`) decodes images, glTF models and sprite animations once and keeps them within a byte budget (`EngineOptions::assetBudget`, 512 MiB by default). When a world is unloaded (`Engine::unloadWorld`, or `Engine::releaseUnusedAssets()` at any time) the engine computes the set of assets the loaded worlds still reference (geometry, sky panorama and backdrops, LUTs, weather and emitter sprites, entity sprites with their atlases and palettes, meshes) and evicts the least recently used assets outside that set until the cache fits. `release(path)` drops one asset. Eviction and reloads bump the cache's generation number, which tells the renderer's `GpuAssets` to drop the GPU copies of assets that are gone; an evicted asset simply decodes again on next use.

## A frame

`MainLoop` pumps SDL events into `InputState` and advances logic at a fixed 60 Hz. Each tick runs, in order:

1. Background world loads advance, then input: raw input queued since the last tick is applied. Each raw input changes between up and down at most once per tick, judged at the threshold of every action bound to it (and at 0.5 for axes and `pressed_inputs`), so a tap shorter than a tick reads as pressed on one tick and released on the next, and an analog pull past a 0.9 trigger threshold that relaxes to 0.6 in the same tick still fires once. A bound input ending in `+` or `-` reads one side of an analog input (a gamepad axis or an input an axis lists as analog); on keys the characters are part of the name, so `key:-` and `key:Keypad +` bind as they are. Text typed since the last tick becomes this tick's `fe.input.text()`, and the IME's latest pre-edit string becomes `fe.input.composition()`.
2. Every world's `beginTick`.
3. The entry module's `update(dt)`; `fe.game` applies its pause and time scales to the worlds, then runs the task scheduler and the scenes' `update` there.
4. Every world ticks: movement, contacts, animation, particles and the events `world:events()` returns.
5. The entry module's optional `post_update(dt)`, for logic that needs this tick's movement and events; `fe.game` runs the scenes' `post_update` and `game.post_updated` there (the field handles world events, encounters, followers and the camera in this phase).
6. Audio: looping positional sounds are updated for every world drawn on the previous frame, each heard from its own camera. Sounds of destroyed entities, unloaded worlds and worlds not drawn stop. Each drawn world's camera becomes the listener for positional one-shots of that world (see [Audio](#audio)).
7. Platform services get their per-tick update (`PlatformServices::update`).

Rendering then calls `draw(alpha)`. Scenes ask for worlds to be drawn (`world:draw()`) and draw UI on the canvas. The renderer draws the requested worlds, then the canvas, then the screen effects, then the editor and error overlay. After the frame the runtime carries out the scripts' requests: title, display changes, screenshots, text entry (IME and on-screen keyboard) and rumble. With vsync off, `MainLoop` paces frames to `game.json`'s `max_fps` (or `--max-fps`; 0 = uncapped) with a `FrameCap`: deadlines advance by whole intervals so jitter does not accumulate, and the wait is a timer sleep followed by a short spin. The window and monitor state is re-read only after an SDL window or display event, not every frame.

## Lua host

- **Sandbox.** Lua 5.4 through sol2. Scripts get base, string, table, math, coroutine and utf8. `io`, `os`, `debug`, `package`, `load`, `loadstring`, `dofile`, `loadfile` and `string.dump` are absent, and `collectgarbage` only accepts `"count"` and `"step"`. The string metatable and every metatable sol2 creates are locked: `getmetatable` returns `false` and `setmetatable` refuses them. Engine objects (`World`, `Entity`, `Camera`, `RandomStream`) show scripts only their documented methods and properties (`LuaHost::sealTypes`, from the members `TypeBinder` registers): any other key reads as nil, including the metamethods and sol2 bookkeeping that sol2 keeps in the same table (`__gc`, `__index`, `__eq`, `__type`, `__name`, `class_cast`, `class_check`...) and non-string keys; assigning anything but a writable property raises an error (`World.spawn is read-only`, `Entity has no field 'speed' to assign`); iterating them with `pairs` or `next`, and `rawget` or `rawset` on them, raise errors. `==` and `tostring` work (`World(<name>)`, `Entity(<id or key>)`, and `Camera: 0x...` or `RandomStream: 0x...` for the others), and objects of different types compare unequal; error messages name these documented types, never sol2's C++ names (`bad argument #1 to 'World:spawn' (World expected, got Entity)`), and sol2 does not print errors to stderr, since every one reaches the script as a Lua error. Methods check the object they are called on, so one type's method cannot run on another type's object. The engine types are not globals, and sol2's own globals (each type's storage and the exception handler, `sol.*`) are moved into the registry after binding, so nothing a script can reach belongs to sol2. `require` searches the game folder, then `lualib/`. `fe.dev.console` (the only way to compile a string of Lua at runtime), `fe.input.feed` and `fe.input.feed_text` (which inject raw input and typed text) are bound in development builds, in `--test`, `--check` and `--write-api` runs (of `fengine_headless` and of `fengine`, which also runs them headless; these runs count as development, with the watchdog, also in a shipped `fengine`), and in `fengine --replay` and `--record` sessions, also of shipped builds. A shipped game played normally has none of them. Development builds add a watchdog that stops a frame (and, under `--test`, a test) that runs longer than 3 seconds, by raising `script watchdog: a frame ran longer than 3.0 seconds` in the script. It interrupts Lua code (a count hook checks the clock every 200000 VM instructions) and the standard library's loops that run in C without executing Lua: pattern matching (`string.find`, `match`, `gmatch`, `gsub`), plain `string.find` and `table.move` check it every 65536 steps through a small patch of the Lua library applied at configure time (`cmake/LuaPatches.cmake`). It cannot interrupt one call of an engine binding or other C code; those bound their own work instead: library strings built in a buffer (`string.rep`, `string.format`, `gsub`, `table.concat`, `string.upper`...) stop at 256 MiB with `string too large`, `table.move` moves at most 2^26 elements per call, `table.unpack` and `string.byte` are limited by Lua's stack size, path searches expand at most 200000 cells, and the sizes, counts and positions bindings accept are bounded (see Errors). Shipped builds have no watchdog, so a script that loops for ever hangs them.
- **Determinism.** String hashing uses a fixed seed and `math.random` is seeded from the run seed, so with `--seed` the iteration order of `pairs` over string and number keys, and `math.random`, repeat between runs. The order of `pairs` over a table keyed by objects (tables, functions, coroutines or engine objects such as entities) depends on memory addresses and differs between runs: keep such keys in a list, or sort them by a stable value (an id, `entity.key`), wherever the order affects the outcome. Prefer `fe.random` streams for game randomness.
- **Errors.** Lua errors never unwind through engine C++: bindings report invalid arguments (unknown enum names such as a sprite mode, text alignment or compass direction, malformed vectors, colours or seeds) as Lua errors, and `tostring` of a value whose `__tostring` fails yields a description instead of an error. Numbers are checked against what the engine stores them in: an integer argument must fit its C++ type (`math.maxinteger` passed where an `int` is stored raises instead of wrapping to -1) and a number argument must be finite and within the float range. Every component of a position, vector, rectangle or colour lies within -1000000 to 1000000 (the world bound), and sizes, counts and speeds have documented ranges (collider radius 0 to 64 and height 0 to 1000, mover and move speeds 0 to 1000, platforms at most 64 x 64, light radius at most 1000, overlays of at most 65536 cells in at most 256 overlays per world...), so no single call makes the engine loop or allocate without end; the C++ conversions of positions to grid cells and hash buckets saturate (`floorCell`) for values from elsewhere, and `world:line_of_sight` traces only the part of the line over the grid. Tags the text resolver returns resolve again, at most 4 levels deep, and more than 1 MiB of replacements for one call raise `Text tags expand too much`. Every path a script names is checked by `resolveInside`, which also refuses a NUL character (`"x.lua\0.png"` would otherwise name `x.lua`). An entity handle carries the entity's serial number, which its world never reuses, so once the entity is destroyed `e:valid()` stays false, `==` stays false and every method raises `This entity no longer exists`, even after entt hands its slot (with a wrapped 12-bit version) to a later entity; `e.key` is that serial. Recursion through C (metamethods, `pcall`, error handlers, and bindings that call back into Lua such as path cost functions, the text resolver, `fe.harness.tick` and `fe.harness.reload`) stops at Lua's limit of 200 nested C calls with a `C stack overflow` or `stack overflow` error. Sanitizer builds (`FENGINE_ENABLE_SANITIZERS`), whose stack frames are several times larger, give the main thread a 256 MiB stack (on macOS through the linker, on Linux by raising `RLIMIT_STACK` at startup) so that limit is reached before the C stack runs out.
- **No script code inside a binding.** A binding runs only the Lua it calls on purpose, so script code can never unload a world or destroy an entity under C++ that holds it. Every table a binding reads (options, settings, vectors, colours, cells, lists) is read raw through `fe::field` (`lua::field`, `lua::get`, the vector and colour helpers, `lua::elements`) and `luaToJson`: no metamethod (`__index`, `__len`, `__pairs`...) runs, and fields must be in the table itself. The entry module's functions and a module's `__reload` are looked up raw too. Every binding registered through `ModuleBinder` and `TypeBinder` runs inside a `LuaHost::BindingCall` (functions and methods also read their own arguments, so errors name documented types), which refuses once the engine is shutting down and holds the garbage collector while the binding's C++ runs, so no finalizer (`__gc`) runs in the middle of it. The Lua a binding does call — a path `cost` function, the text resolver, the console, module loading, the test harness's ticks — runs through a `LuaHost::Callout`, with the collector running, and those bindings tolerate anything it does: path searches keep the world alive and only read the grid, which no script call can reshape; the text resolver is held by a wrapper that `fe.text.resolver` never destroys, so a resolver can replace or remove itself mid-call, and its markup is parsed before the fonts are chosen. A resolver that resolves markup with tags through `fe.text` nests; more than 8 nested resolver calls, or the watchdog stopping a resolver, raise one error from the outermost `fe.text` or `fe.canvas.text` call instead of an error per level.
- **Shutdown.** The engine first marks the host as shutting down, so every binding (and `require`) raises "engine is shutting down"; it then releases its references into the Lua state (worlds, the entry module, the text resolver) and closes the state while the rest of the engine is still whole. Finalizers that run as the state closes therefore cannot load worlds, spawn entities or create new references into it. Module binding functions are owned by the host and outlive the state (sol2 finds a stored function's destructor by its C++ type's printed name, which closures can share).
- **Entry.** `main.lua` returns `{init, update, post_update, draw, file_changed, validate}`; every field is optional. `fe.game.main` and `fe.starter.main` build that table.
- **Waiting is Lua.** `fe.task` is a pure-Lua coroutine scheduler: `wait`, `wait_until`, `wait_signal`, `all`, `race`, `join`, `cancel`, `detached`, `finally` and `ensure`. Cancelling or failing a task cancels its children and runs its cleanup; children of a task that finishes normally keep running. Engine calls return immediately; scripts wait on state, signals or `world:events()`.
- **Reloading assets.** Data tables reload with validation, and a broken edit keeps the old data. Maps, images and shaders reload too. Errors show in a dev overlay with a traceback and are logged in release builds.
- **Source layout.** `engine/script/LuaHost.cpp` holds the state, the sandbox, type sealing, `require` and the console; `ModulePatcher.cpp` the hot-reload merge below; `LuaJson.cpp` the Lua-JSON conversion (a table becomes a JSON array only when its keys are exactly 1..n, so `{1, nil, 3, x = 1}` is an object with `#1`, `#3` and `x`, nothing dropped); `GcHold.cpp` the collector hold of `BindingCall`/`Callout`, the only file that includes Lua's internal headers, guarded by `static_assert(LUA_VERSION_NUM == 504)` and named after the `GCSTPUSR` bit it touches. Both watchdog hooks find the host through one registry key (`LuaHost::of`). The module cache is a registry reference only: scripts have no `fe._loaded` through which a kit's state could be split. `Convert.h` (the argument conversions bindings share) declares; `Convert.cpp` defines. `BindingDocs` checks at registration, in development builds, that every LuaLS signature declares as many parameters as the binding's C++ reads, and every build refuses to write the API files (`--write-api`, hence `tools/ci/check_api.py`) while a signature disagrees. Functions and methods that take no arguments reject any they are given (`'fe.app.title' takes no arguments (got 1); it only reads, use fe.app.set_title to change it`), so a getter can never be mistaken for a setter.
- **Components from Lua.** The eight entity component methods go through one `component<T>(name, set, read)` helper (`EntityBindings.cpp`): a table validates into a copy of the component and stores it only when every field passed (a rejected `e:mover{speed = 5, climb_speed = -1}` changes neither), no argument reads the component as a table (nil when absent; nothing is added), nil removes it. `world:spawn` destroys the entity it created when a component table is rejected, so its id is free for the retry.

## Hot reload

In development builds the runtime watches the game folder and `lualib/`. When a Lua file changes, the module that was loaded from it is reloaded. This is the contract modules can rely on:

1. The file runs again, producing a fresh copy of the module. If it fails to compile or raises an error, the error is reported and the live module is left exactly as it was.
2. If the module returned a table both times, the fresh table is merged into the live one, which is the table every `require` caller already holds:
   - **Code is replaced.** Every function the module itself defined is replaced by its fresh version. A function that other code stored in the module (the game assigning `kit.on_open = ...`) is kept.
   - **Data is kept.** Non-function values the live table already has (numbers, strings, booleans, userdata, tables) keep their live value, also when the fresh table holds a function under that key (`M.handlers = {}` edited into `function M.handlers()` keeps the live table; a `__reload` adopts such a change). Keys only the fresh table has are added. Keys only the live table has, such as values added at runtime or functions deleted from the source, are never removed.
   - **Nested tables merge recursively** under the same rules, including their metatables. A class table (`Class.__index = Class`) therefore stays the same table, so existing instances use the new methods. A value that is another loaded module (a `require` result) is a reference: it is never merged, and the fresh reference replaces the live one.
   - **Locals stay connected.** New functions are rewired so they see live state: an upvalue that refers to a fresh table refers to its live counterpart instead (code such as `local M = {} ... M.count = M.count + 1` updates the live `M`). Each module-level local such as `local tasks = {}`, `local now = 0` or `local box` is one variable shared by every old closure that captures it and every new function the merge reaches (the module's functions and the functions in its tables), so assigning it through any of them (`box = nil`, `tasks = {}`) is seen by all of them. Its value after the reload: local tables merge under the rules above; other live values are kept, also when the fresh copy's is nil; a live nil takes the fresh value; local functions, locals holding another module, and locals whose type changed take the fresh value, also for old closures (a function the game assigned at runtime is kept). A local only the new code captures starts with its fresh value. A name that either version uses for two different variables (shadowing in nested blocks) is not joined: the new code keeps its own variables.
3. Then, if the module has a `__reload` function (the new one), it is called as `__reload(live, fresh)`. Use it to adopt values that should change when edited (`live.speed = fresh.speed`), rebuild derived data, or re-register hooks. Its errors are reported.
4. If either version is not a table, the module cache takes the fresh value; code that already holds the old value keeps it.

Consequences for module authors:

- Top-level code runs again on every reload. Registrations made there (signals, effect hooks, input definitions, schema or data registration) must be idempotent, for example keyed by name, or move into `__reload`. `signal:connect(fn, priority, key)`, `save.add_meta(fn, key)` and `i18n.add_resolver(fn, key)` replace an earlier registration with the same key; registries (`field.define`, `field.verb`, `schema.define`, `story.define`, ...) are keyed by name. The library kits register this way, keep their state in module fields, state sections or module-level locals, and use `__reload` for edited constants. `fengine_headless --test` reloads every stateful kit in the middle of a game (`lualib/tests/game/tests/reload.lua`, through `fe.harness.reload`).
- An edited constant does not apply until restart unless `__reload` copies it. Keep tunable constants as module fields, which `__reload` can copy, rather than locals, which it cannot. The kits' settings tables (`field.settings`, `dialogue.style`, `cutscene.settings`, `ui.toast_settings`, `worldmap.style`, `follower.max`, `input.defaults`, `save.autosave_slot`, the screens' constants, `menu.dim` and the theme's colours, skin, font and sounds) are adopted with `tablex.adopt(live, fresh, baseline)`: a value is taken from the edited file when its live value still equals the file's previous value (kept in the module's `file_defaults`), so a value the game changed at runtime (`field.settings.followers = 1` in `setup`, `theme.set{...}`) survives the reload. `camera.defaults` and the day/night keyframes are copied whole. `theme.__reload` adopts underneath an active preset such as high contrast and re-applies the preset; `menu.__reload` merges the file's pages into `menu.pages` by id, so a page the game inserted keeps its place and its functions; `input.__reload` defines the adopted actions again and re-applies the player's rebindings.
- Functions created by the top-level code and handed to another module (for example `signal.connect(fn)`) are new closures that the rewiring never reaches: each local they capture is their own copy, holding the live value at reload time. Later assignments to the module's local are not seen by them, so a table such a listener reads must be mutated in place, never replaced (the kits do this: fe.field clears its entity list for a new map instead of assigning a new one, because its `state.changed` listener reads it).
- Lists merge by position, so a registry kept as a list (hook lists) can pair a live entry with a different fresh one. `fe.effects` therefore re-registers its own hooks by id in `__reload`.

The battle, RPG and effects kits follow this: their top-level registrations are keyed (effect hooks, formulas and handlers by id or name, schemas and state sections by name, i18n defaults by key), installers such as `rpg.install` run once, and the party's actor cache checks each object against the saved record instead of listening to a signal. Tests reload these modules in the middle of a battle with `fe.harness.reload`.

## World

`fe.world.load(name, map)` creates a named world, and several can exist at once (the field stays loaded while a battle stage renders). `fe.world.load_async(name, map)` does the slow parts in the background for loading screens: a worker thread parses `map.json`, then `AssetCache`'s worker decodes the map geometry, panorama, backdrops, LUTs, emitter and weather sprites and finally the sprites' atlases, while `fe.world.load_progress(ticket)` reports 0..1. `fe.world.finish_load(ticket)` builds the `World` on the main thread from the cached results. A world owns:

- **Entities.** Generational handles with a transform, sprite (directional clips, tint, flash, outline with a width in atlas texels, palette swap), mesh (glTF node animation), light, emitter, mover, collider, platform, tags and a free `props` table. `world:query` hands back handles, or with `fields` a struct of arrays (`n`, `x`, `y`, `z`, `layer`, `id`, `cell_x`, `cell_z`, `entity`) so a HUD or tactics kit polls two hundred positions a tick with a handful of tables.
- **Map grid.** Multiple layers with per-cell height, walkability, ramps (with a per-cell rise) and tags; links between layers for bridges; ladder links; points; zones; placements. C++ never interprets placements or props; `fe.field` spawns them by type.
- **Queries.** A* paths and Dijkstra reachability with step limits, blocked and no-stop cells, zones of control (cells that end movement), horizontal gap jumps (along the axes, and the diagonals with `jump.diagonal`), ladders (`ladders = false` leaves them out), a body `footprint` (cells per side, anchored at the unit's cell and extending towards +x and +z: every cell of it must be enterable; wide bodies do not climb ladders), `fly` (walkability and height steps are ignored; grid bounds, blocked tags and blocked cells still hold), a passability class (`blocked_tags`: cells carrying one cannot be entered; `required_tags`: when given, cells carrying none of them cannot be entered; both hold for flyers) and an optional Lua cost function per step; line of sight, shapes, raycasts (grid, cliff faces, map colliders, solid entity colliders and sprites; triggers only with `solid_only = false`) and mouse picking of cells and sprites. Ties between equal-cost cells break on the cell key, so paths are the same on every platform. Path and reach results mark steps that jump or climb, so presenters can animate them. A search expands at most 200000 cells (stale queue entries do not count); an A* search that stops there before settling the goal says so (`Route::truncated`, `truncated = true` on the Lua list) instead of passing off a partial result as the cheapest route, and a reach search that stops there reports `Reach::truncated` the same way (a zero-cost rule cannot flood the grid). A goal the body cannot enter (unwalkable, a blocked or missing tag, a blocked cell) ends an A* search before it expands anything, and so does a goal in another connected component of the grid: `Grid::component()` labels the cells under the most permissive walking rules (4-neighbour walkable cells of a layer joined through every step and ladder link, ignoring heights, tags and blocked sets), so different labels mean no walking route can exist while the same label promises nothing and the search runs as usual. The labels are computed on first use and cached against `Grid::revision()`, which every mutator bumps (the non-const `at()`, `setCell`, `setLinks`, `addLayer`; `world:set_cell`, the editor and platform overrides all go through them), and the precheck is skipped for rules that fly or jump gaps, the two ways a route leaves its component. A mover never follows a truncated route: `move_to` stops and emits `blocked`, as when no path exists.
- **Movement.** Movers walk, jump and climb to targets or along given routes (`move_to(nil, {path = cells})` follows a reach path in one call, carrying leftover distance from waypoint to waypoint), colliding against the grid, the map's collision boxes and other solid entities through a spatial hash. `move_to(target)` plans with the mover's step limit and gap jumps, diagonal steps, ladders and its own tag class; given path rules (the same rules `world:path` takes) it plans with those instead, the mover's footprint and fly always applying. A mover's passability class is `Mover::blockedTags`/`requiredTags` (`e:mover{blocked_tags = {"lava"}, required_tags = {"water"}}`): `Grid::canStand` refuses a cell carrying a blocked tag or, when required tags are set, none of them, so standing, stepping, platform carry, `can_occupy` and landings all obey it, as the planner does through `StepRules`. This is the vehicle class: a boat is `mover{fly = true, required_tags = {"water"}}`, which floats over unwalkable water cells and can neither path nor steer onto the bank; a swimmer is a walker whose class allows water. The footprint is grid occupancy, for planning and standing: body-against-body collision uses the collider radius (up to 64), so a two-cell cart still blocks and is blocked by its collider's disc. A mover is in one motion at a time (`Mover::motion`: none, route, jump, climb or launch; a route passes through its jumps and climbs and resumes after them). Every command (`move_to`, `follow`, `stop`, `jump`, `launch`, `place`) first ends a jump, launch or climb in progress: a jump lands at once on the ground under the body (the standable layer nearest its height) or, over a void, at the nearer end of its arc, a launch on the highest standable surface under the body (else the lowest layer's), both emitting `landed`; a climb steps off at the nearer end of the ladder, on that end's layer, and emits `climb_end`. No command leaves a body in mid-air or on a ladder. `launch(velocity)` (`World::launch`, `entity:launch`) is a ballistic flight under `MovementTuning::gravity` (20 units/s², `set_movement_tuning{gravity = ...}`): the horizontal velocity holds until a solid body, a collision box, a cliff face (ground more than a step above the body) or the grid's edge stops it, after which the body drops straight down; it lands on the first surface it falls onto that it may stand on (any layer, by its tags, fly and footprint), with a jump's landing validation at that moment (nearest free spot within `landingSearch`, else it lands there anyway and `blocked` follows `landed`), and over nothing standable on the lowest layer's surface. It emits `jump_start` and `landed`; a zero velocity above the ground is a fall, a launch during a jump or launch replaces it from where the body is, and a launch during a climb is an error. A jump's landing is checked at take-off: a landing inside a collision box or a solid body moves to the nearest free standing spot within `MovementTuning::landingSearch` (1 unit), and with none the jump is refused with `blocked` (`jump()` and route jumps alike). Bodies are upright cylinders from the feet: two block each other only where their height ranges overlap, so a short crate is walked over from above and a tall body under a low bridge blocks the deck. Two solid bodies that overlap (spawned on one spot, pushed together) can always move apart: a step that shrinks an existing overlap is allowed, a step that deepens it is not. Path finding and movers change layers through one shared rule (`Grid::traverseLink`) and take ladders through another (`Grid::ladderStep`); inside a directed link cell the two surfaces are compared at the junction edge (where path finding tests them), so every planned path is walkable for any body radius up to 0.49. The thresholds (arrival and snap distances, the stuck share and time, the route-jump arc, the landing search and gravity) are `MovementTuning` on the world (`World::movementTuning()`; scripts read them with `world:movement_tuning()` and change them per world with `world:set_movement_tuning{arrive_distance = 0.1, stuck_seconds = 2, ...}`, ranges in [api.md](api.md)), with the engine's defaults. The resulting events are delivered through `world:events()`: `contact_begin`, `contact_end`, `arrived`, `blocked`, `jump_start`, `landed`, `climb_start`, `climb_end`, `cell_enter` (a mover's cell, `x`, `z` or `layer`, changed; the event carries the new cell; a mover's first cell is not an entry), `anim_event`, `anim_finished`, `zone_enter` and `zone_exit`. Events naming an entity destroyed before they are read are dropped, so no event arrives with `a` or `b` missing: a contact with something destroyed in the same tick is never delivered, and destroying an entity ends its contacts without a `contact_end`.
- **Presentation.** Environment (ambient, sun, fog, shadows, water, sky gradient and backdrops, weather, post-processing with two blended LUTs, bloom, tilt-shift, tone mapping, pixelation), particles, tile overlays with pulse, path arrows and a cursor, and a camera. The camera is an orbit (target, yaw, pitch, distance, fov) whose projection is perspective or, with `orthographic`, parallel: the eye stays where the orbit puts it, the view covers `ortho_height` world units vertically (by default what the perspective view covers at the target, so toggling keeps the framing), and shadows, picking, `project`, `ray`, pixel snapping and the post pass's depth reconstruction follow it. `Camera` interpolates every value between ticks, the orthographic height included.

`World` owns the registry and hands it to its systems, one file each in `engine/world/`: `Movement` (movers, routes, jumps, ladder climbs, platforms, attachments, link switching, cell events), `Collision` (static boxes, the spatial hash, ray tests, contacts and zones), `Animation` (sprite and mesh clips, frame events, sprite quads for picking), `Particles` (emitters, bursts and weather) and `Overlays` (cells, path arrows, cursor), plus `Camera`. Each tick runs them in that order: movement, platforms carry their riders and move their grid overrides, attachments, cell events, animation, particles, contacts, zones. The camera starts on the map's `start` point (else its first point, else the middle of the grid).

- **Platforms.** An entity with a `platform` component is a moving surface whose top is its position and whose footprint is `size`. Riders (movers and colliders on its top and inside the footprint it had when the tick began, measured where they stand after moving, so a mover that stepped off this tick is not dragged along; not jumping, climbing or attached) move with it each tick; riders that collide when walking are still stopped by solid entities that are not aboard, by collision boxes and by terrain they cannot stand on (sliding along the obstacle where one axis is free) and left behind. Grid cells whose centre it covers on its layer are rewritten as walkable at its height before its riders move, and restored when it moves on, unless a script changed them in between. Move platforms with `mover{collide = false}` or `place`.
- **Attachments.** An entity with a `parent` follows it: its `offset` is turned by the parent's yaw (as the renderer turns the parent's mesh) and added to the parent's position; it takes the parent's layer. Parents are placed before their children whatever the entity order, so chains of attachments move as one. Being carried, by a parent or a platform, is not moving: a sprite's automatic move/idle clip follows the mover's own walking, jumping and climbing only.
- **Static data.** Map colliders (plus geometry marker boxes) and map emitters are turned into collision boxes and emitter entities by `World::rebuildStatic()`, at load and after every editor edit; lights are read from the map each frame. The boxes are bucketed like the spatial hash, so a body tests only the boxes near it.

- **Pause and time scale.** `world.paused` stops a world's tick (it still renders and scripts can still change it); `world.time_scale` multiplies its tick length (slow motion, hit-stop, fast-forward; 0 to 10, since longer steps would let movers pass through walls). The engine applies both when it ticks worlds.
- **Spatial hash.** Colliders enter and leave the hash as the components are added or removed, and spawn, `place`, movement, platform carry and attachments keep it current, so `can_occupy` is exact during the script update and nothing is rebuilt per tick. Code that writes `Transform::position` behind the world's back (the editor) calls `World::refreshCollision()` afterwards; `rebuildStatic()` refreshes too. Queries reach out by the largest collider radius, which follows collider construction and updates; C++ that changes a collider's radius does it through `registry.patch` or `replace` (the Lua bindings do), so a collider grown by a script blocks at once. `can_occupy` tests the entity's own body: its mover's radius, footprint, fly and tag class, else its collider's radius, and its collider's height. Inside a link cell, standing room counts the other surface of every link of the cell whose surfaces meet, as `Grid::traverseLink` does.
- **Events.** Events wait in a queue until `world:events()` reads them. The queue keeps at most 4096; when nobody reads it, the oldest are dropped with one warning per overflow.
- **Zones** report entities with a transform and a mover or collider. Scenery without either never triggers zones.
- **Weather** kinds are data: `@fe/assets/weather.json` holds the emitter settings per kind (`rain`, `snow`, `leaves`, `embers`, `dust`, `custom`) and a game's `data/weather.json` adds or replaces kinds.
- **Particles** are stored in world space. Emitters with `world_space = false` keep their particles' offsets from the emitter and move them with it; `max` caps the live particles per emitter. The particle system counts each emitter's live particles itself, so giving an emitter new settings keeps the cap of the particles it already has alive.
- **Animation clips** are always looked up through `SpriteAnimation::clip()`: an unknown clip name shows, fires the frame events of and finishes (`anim_finished` with the requested name) like the clip it falls back to, `idle` or else the first clip.
- **Light flicker** noise is seeded per light, map lights by their position (a hash of it, so lights authored at the same position flicker together and moving one changes its phase) and entity lights by their entity, so adding, removing or reordering lights never changes another's phase.

## Platform

The core has no window or devices; it records what scripts ask for and what the runtime reports, so everything below also runs headless.

- **Display.** `Engine::display()` is the window and monitor state (`engine/platform/Display.h`): fullscreen mode (window, borderless or exclusive), window size, vsync mode, monitor, the monitors' exclusive modes and whether the back buffer is HDR (`hdr`, set once by the runtime from the format bgfx gave it; false headless). `fe.app.set_display` validates a change, queues it in `AppRequests` and shows it in `fe.app.display()` at once; after the frame the runtime moves, resizes or switches the window (`Window::apply`), sets the renderer's vsync and reads the real state back. Adaptive vsync is the runtime's `AdaptiveVsync`: it presents in sync while frames keep up with the monitor's refresh rate and stops waiting for vertical blank when they fall behind. Headless runs report one monitor the size of `game.json`'s window. The engine does not persist display settings; `fe.config` does.
- **Text entry.** `fe.input.text_begin(rect, kind)` and `text_end` are requests on `InputState`; `SdlInput::apply` starts SDL text input with the kind (`text`, `name`, `number`) and the IME candidate area converted from canvas to window coordinates. SDL opens an on-screen keyboard where the system has one, including Steam Deck's. Committed text and pre-edit strings come back as SDL events and are queued like other input, and `--record` writes both into the replay. Pre-edit strings count only while the game's text entry is active, so events still queued when `text_end` runs don't bring a composition back, and losing window focus ends the composition.
- **Gamepads.** `SdlInput` describes every connected gamepad to `InputState`: number, name, layout (`xbox`, `playstation`, `switch`, `steamdeck` from the Deck's own controls, or `generic`) and rumble capabilities. `fe.input.device_type()` follows the device used last, for button prompts. Rumble requests (handle and trigger motors) are played after the frame and stopped when the window loses focus.
- **Locale.** The runtime passes SDL's preferred locale to the engine as a BCP 47 tag (`fe.app.locale()`); headless runs, replays and recordings use `en-US` so they don't depend on the machine.
- **Platform services.** `PlatformServices` (`engine/services/PlatformServices.h`) is the store interface behind `fe.platform`: unlocks and stats, plus a per-tick `update`. `LocalPlatformServices`, the default, keeps them in `<user data>/platform.json`: unlocks are written at once, stat changes are coalesced to one write per 5 seconds while dirty and a final one at shutdown. A port supplies its own through `EngineOptions::platform` or `RuntimeOptions::platform`.
- **Library lookup.** `findLibraryRoot` looks for `lualib/` next to the executable (`<exe dir>/lualib`, an app bundle's `Resources/lualib`, `<exe dir>/share/fengine/lualib`). Development builds also search the folders above the executable and fall back to the source tree; shipped builds (`FENGINE_DEV` off) look nowhere else. Both programs start from the executable's path as the operating system reports it (`executablePath`: `_NSGetExecutablePath`, `/proc/self/exe`, `GetModuleFileNameW`), never from `argv[0]`, so an installed `fengine_headless` found through `PATH` works from any directory.
- **User data.** The per-user folder (saves, settings, `platform.json`, log) is `SDL_GetPrefPath("fengine", <id>)`, keyed by `game.json`'s `id` (derived from the title when the title is plain ASCII words), never by the display title, so renaming or translating the title keeps every player's saves. `--user-data <dir>` overrides it.
- **User files.** `fe.fs.user_list`, `user_read`, `user_write` and `user_remove` reach `<user data>/files/` only: every path goes through `resolveInside` (NUL and `..` refused), writes are atomic (`writeTextAtomic`: flushed temporary, rename, folder flush; binary-safe), a file holds at most 16 MiB and the folder 256 MiB in all. It is where a game keeps what the player drops in or exports: mods (`files/mods/<name>/mod.json`, listed and read by the game's own loader), exported replays, screenshots of its own. Nothing here is loaded by the engine itself.
- **Log and crashes.** `fe::log` (`engine/core/Log.h`) is thread-safe and writes to stderr and, once the runtime opens it, to `<user data>/log.txt`; the previous run's file is kept as `log.txt.1`. Messages below the minimum level are dropped (`debug` in development builds, `info` otherwise; `setLogLevel`). The file is flushed after every error, and the last 32 lines are kept in a ring buffer. `setLogSink` installs one hook that every record passing the filter also reaches (level and message), called on the logging thread outside the log lock, so a telemetry or crash reporter can forward records; a record the hook logs itself is written but not fed back to it. `EngineOptions::logSink` installs it for the engine's lifetime. The runtime installs a minimal crash handler (fatal signals; the unhandled-exception filter on Windows) that flushes the log and writes `<user data>/crash.txt`: one line naming the signal, then those 32 lines. It walks no stack and allocates nothing.
- **Saves.** `SaveStore` writes through a `SaveBackend` (`engine/services/SaveStore.h`: read, write, list, remove and a cheap stat per key). The default `FileSaveBackend` keeps files in the user-data folder and the previous version of each as `.bak`: `writeTextAtomic` writes the new data to a temporary and flushes it (the one data fsync), renames the current file to `.bak` (POSIX `rename`; `ReplaceFileW` on Windows, never a copy), renames the temporary into place and flushes the folder entry once, so a save costs the write itself and two directory updates; a current file that is blank or, for JSON, cut short is replaced instead of kept, so a truncated file never takes the place of the last good backup. A crash between the two renames leaves the file missing and `.bak` holding the last version, which `SaveStore` and `readJsonOrBackup` read in its place. A port supplies a cloud or console backend through `EngineOptions::saveBackend`. A slot document is capped at 16 MiB, and each slot's `meta` is also written to a `<slot>.meta.json` sidecar so `fe.save.list` reads summaries without parsing the saves; a sidecar that is missing or no longer matches the slot's size falls back to the full read. Thumbnails are PNG files the asset cache reads as `user://` images, so they stay in the user-data folder whatever the backend. Blobs (`fe.save.write_blob`, `read_blob`, `remove_blob`, `blobs`: binary strings up to 16 MiB each, named like slots) go through the backend's `writeBlob`/`readBlob`/`removeBlob`/`listBlobs`, whose defaults store them as the key `saves/<slot>.<name>.blob`, so a port overrides them only to use its own blob storage; `remove(slot)` deletes the slot's blobs with it.
- **Frame stats.** `Engine::stats()` (`FrameStats`) holds the last frame's Lua update and draw times, the milliseconds between the last two frames and the worlds' draw calls (both filled by `MainLoop` after rendering, 0 headless) and the `fe.dev.zone` timings; `fe.dev.stats()` returns them with entity, particle and Lua memory counts for quality settings and debug overlays. `fe.app.format_number` formats numbers with the decimal and group separators of a language (`engine/core/NumberFormat.cpp`: a table for en, de, fr, es, it, pt, ja, zh, ko, ru, pl, nl, sv, tr keyed by the language subtag of a BCP 47 tag, `fe.app.locale()` by default); `fe.i18n.number` applies the current language.
- **Canvas fit.** `game.json` `canvas_fit` is `letterbox` (default: the virtual canvas keeps its size and is centred with bars) or `expand` (the canvas widens to the window's aspect ratio, never below the configured width, so UI anchored to the edges reaches an ultrawide screen's edges while the 3D world fills it either way).

## Text

`engine/text` parses markup into units (characters, icons and timing marks; typewriter effects count them), lays them out and paginates them; the canvas turns layouts into quads. Fonts are named sets of faces (bitmap `.fnt` and TrueType), with fallbacks scaled onto the primary face's baseline and pair kerning; a font `<name>.bold` (or `bold` in `fe.text.font`) is the `{b}` face, otherwise bold glyphs are drawn twice, 1px apart.

- **Markup.** `{color}`, `{icon}`, `{wait}`, `{speed}` (`{speed:0}` = instant), `{size}`, `{b}`, `{shake}`/`{wave}` and `{ruby:base|reading}`; other tags go to the script resolver. `{size}` and `{b}` nest: `{/size}` restores the size in force before its `{size}`, and text stays bold until as many `{/b}` as `{b}` have closed. Pagination writes pages back as markup, so every tag survives it; a ruby base the layout had to break (one wider than a line) goes whole to the later page when the break is a page break, so a page's markup never holds half a `{ruby:}` tag.
- **Lines.** Lines break at spaces and between CJK characters, following kinsoku rules: no line starts with closing punctuation, small kana or the prolonged sound mark, and none ends with an opening bracket (the character before moves down instead). A ruby base never breaks; a line is as tall as its largest glyph plus room for its readings, which sit centred above their base at half size and appear with it. A reading wider than its base spreads the base instead of overhanging it: the extra width goes half a share before the first base character, a share between characters and half a share after the last, as Japanese typesetting does.
- **Effects.** Laid-out glyphs and their canvas quads carry `effect` (shake or wave) and `phase` (the unit index); the canvas renderer moves them.
- **Scripts.** Right-to-left scripts (Arabic, Hebrew) are not supported: there is no bidirectional reordering or shaping.

## Rendering

`FrameRenderer` draws each frame in this order:

1. **Worlds**, in `world:draw()` order. Each world renders its 3D scene into an off-screen HDR target (the output size over `post.pixel_scale`, 1 to 8: a whole scale divides exactly and the composite upsamples with nearest filtering, a fraction rounds and is filtered bilinearly, `sceneSizeFor` in `FrameMath.h`), then post-processes it over its output: the composite writes premultiplied colour (the scene times its coverage plus the bloom and near-field blur that reach past it) and blends it ONE/INV_SRC_ALPHA, which is exactly straight-alpha compositing for an opaque world. A later world draws on top of an earlier one. Where a world has no sky (`sky.mode = "none"`) and no geometry, the background stays transparent, so the worlds drawn before it show through, and a glow halo that extends past the world's geometry still lands on them. A draw goes to the whole screen, to a screen `rect` (picture-in-picture), or into a named render **target** that `fe.canvas.image("rt:<name>")` shows (minimaps, 3D portraits; a target holds premultiplied colour, so the canvas blends it premultiplied, its colour premultiplied too); its optional `camera` replaces the world's camera for that draw only, so one world can be drawn several times per frame, and its optional `post` replaces fields of the environment's post-processing for that draw (a minimap without depth of field or bloom). A draw camera is interpolated like the world camera: `FrameRenderer` keeps, per world, target and order of such draws, the values of the previous tick and blends towards the current ones with the frame's alpha (`DrawCameras` in `FrameMath.h`); a draw missing for a frame starts snapped. Scene, post and render targets are pooled by size (or name) and released after a frame that didn't use them. The number of draws per frame is limited by bgfx's view count: 24 views for the scene (16 of them light-shadow tiles) plus 4 to about 30 for its post-processing, depending on its settings.
2. **Scene captures** (`fe.save.thumbnail`): the frame so far, worlds only, is copied to a read-back texture. Once the GPU has read it back (a frame or two later) it is box-filtered to at most 480 pixels across and written as PNG through a temporary file.
3. **The canvas UI**, composed in sRGB space. Glyph quads with an effect (shake, wave) move by whole canvas pixels at draw time.
4. **The screen pass**, which applies `fe.screen` to everything, UI included, while copying to the back buffer: the freeze-frame, letterbox, transition (`fade`, `swirl`, `mosaic`, `wipe`, `iris`, `shatter`), radial blur, chromatic aberration (one rule with the post pass's: with amount a, red is read a × 3% further from the screen centre and blue as much nearer), fade and flash, then the output encoding: nothing for the 8-bit back buffer (the frame is already sRGB), or, for an HDR back buffer (`game.json` `hdr_output`, `--hdr`; `Renderer::output()`), the frame decoded to linear light and scaled so its white sits at `hdr_paper_white` nits, as scRGB (RGBA16F: paper white over the 80-nit reference, or 1 on macOS where the extended-range layer's 1.0 is the display's SDR white) or as Rec. 2020 PQ (RGB10A2). `OutputColor`, `outputColor` and `packOutput` in `FrameMath.h` are the CPU side; the 8-bit path is bit-identical to a build without it. It runs with no world drawn too. `tint` multiplies only the 3D scenes. `fe.screen.freeze()` copies the frame that is on screen (last frame's worlds and canvas, before screen effects) into a texture that the screen pass shows instead of the live frame, which keeps rendering underneath; a transition then goes from the held image to the live one instead of to its colour, which is how battle intros swirl or shatter the field into the battle. `fe.screen.unfreeze()` releases it.
5. The editor and the error overlay (ImGui).

Each world's scene, in `WorldRenderer`:

1. **Sun shadows.** Three cascades are fitted to the camera frustum (or an orthographic camera's view box), without screen shake, out to `shadow_distance` past the camera focus. Each cascade box surrounds a bounding sphere of its frustum slice and is snapped to whole shadow texels, so shadows don't shimmer while the camera moves. Casters are culled per cascade. `shadow_strength` and `shadow_bias` are environment data.
2. **Light shadows.** Point and spot lights with `shadows` (`castShadows`) render depth into one shared atlas of 16 tiles of 512×512: a spot light takes one tile (its cone), a point light six (a cube). Each frame the lights in view are ranked by unflickered brightness falling off with distance from the camera focus, and tiles go to the best ones that still fit, so at most 16 spot lights, or two point lights and four spot lights, cast shadows per world; the rest light without shadows. Map chunks, meshes and opaque sprites cast (sprites with their camera-facing quad, so a light level with a sprite sees it edge-on); blended sprites and mesh parts, including opaque sprites faded by a tint alpha below 1, cast nothing rather than a full cutout. Everything lit receives them, sprites per pixel. Lookups are biased along the normal and towards the light by about one shadow texel and filtered with four hardware comparisons.
3. **Sky** (colour, gradient with clouds, or panorama) and backdrop cards.
4. **Map geometry**, baked into world-space indexed 8×8-unit chunks (each chunk remaps only the vertices it uses), then **mesh entities** with glTF node animation. Both are frustum-culled by their transformed bounds, and normals use the inverse-transpose matrix. Opaque mesh parts drawn more than once in a view (the same model part and shader) go out as one instanced draw, in the main pass and in every shadow view (`vs_world_instanced`, `vs_shadow_instanced`: the instance data is the model matrix and the tint, and the normal matrix is the cofactor matrix over the determinant); single parts draw as before. glTF sampler wrap and filter modes are honoured, textures have mip chains, and anisotropic filtering follows the environment's `anisotropic` setting. Materials use the base colour, normal map (with its `scale`; per-vertex tangents come from the file or are generated from the UVs, area weighted and smoothed across shared vertices) and emissive texture times `emissiveFactor` and `KHR_materials_emissive_strength`; emissive light is added unlit, so values above 1 bloom.
5. **Sprites and particles**, batched. Every quad goes into one per-frame vertex buffer, and consecutive quads with the same textures, shader and blend mode are drawn together. Sprites are lit at a probe `sprite_light_height` above their feet and support flash, outline (`outline_width` atlas texels out, packed in `u_sprite[1].w`) and palette swap. A sprite sheet may add a normal map and an emissive mask laid out like its atlas (`normal`, `emissive` in the `.anim.json`): normal-mapped sprites are lit per pixel by the sun and point and spot lights, so lights move across them; the mask's colour is added unlit. Sprites with a `silhouette` colour first draw that colour where map geometry or meshes hide them, so characters stay visible behind walls; sprites in front still cover it. `mode = "decal"` lays a sprite on the grid surface of its layer: it is cut at cell borders and each piece follows that cell's height and ramp (`flat` stays one quad at the feet's height). With `environment.pixel_snap` (or a sprite's own `pixel_snap`) a sprite's anchor moves to the centre of a whole scene pixel every frame, so pixel art moving under the low-FOV camera doesn't shimmer. Particles use the frames of their sprite's `idle` clip (or its first clip) over their age, honour `unlit`, and are sorted with the other transparent draws. They fade out as they come nearer the camera than 30% of its distance to the focus and vanish at 10%, so weather that drifts past the lens (falling leaves spawn at about camera height) doesn't cover the screen as a blurred, blooming blob.
6. **Grid overlays**, path arrows (a strip with an arrow head) and the cursor.
7. **Blended draws**: mesh parts, water, sprites and particles whose blend mode is not `opaque`. They are drawn in passes: `alpha` and `premultiplied` sorted back to front, then `multiply`, then `additive`. Within the first pass water surfaces come first (back to front among themselves) and are the only blended draws that write depth: every blended draw after them is depth-tested against the surface, so a sprite or particle above the water draws over it and one below it is hidden by it, whatever their distances (`TransparentKey::water` in `DrawOrder.h`; a single back-to-front order cannot place a large surface against both at once). Fog fades additive glow and multiply darkening instead of tinting them. Sprites default to `opaque` (an alpha cutout that writes depth; a tint alpha below 1 makes them `alpha`), particles to `alpha`, and mesh parts to their glTF alpha mode unless the mesh sets `blend`.
8. **Water.** Before the first water surface, `SceneTarget::copyOpaque` copies the opaque scene's colour and depth (`colorCopy`, `depthCopy`; any pass that needs the scene behind it can use them). Water then refracts the copied scene through its waves (`water.refraction`, ignoring what stands in front of the surface), tends to `water.deep_color` with the depth behind it, reflects the copied scene by marching the reflected ray through the copied depth (`water.reflection`; misses show the sky's horizon colour) and adds fresnel and sun specular. Screen-space reflection only shows what is on screen.
9. **Distortion.** Sprites and particles with `distort` draw no colour; they add screen offsets into an RG16F buffer, tested against the scene depth (so walls in front hide them): the alpha gradient of their image bends like a lens (a ring makes a shock wave) and an animated wobble makes heat haze. The post pass offsets its scene lookups by it, clamped to 3% of the screen.

**Game shaders.** A mesh material (glTF material extras or node custom property `shader`, or the mesh component's `shader` for every part) or a sprite (`shader`) can replace the engine's fragment shader with the game's `shaders/fs_<name>.sc` ([authoring](authoring.md#game-shaders)). `CustomShaders` (owned by `FrameRenderer`, shared with the post pass) compiles and loads them like post shaders and pairs each with the engine vertex shader it draws with; draws resolve names to stable slots once and cache them, and a shader that cannot be compiled, loaded or paired is reported once and the engine's own is used. Each draw of such a shader gets `u_params` (vec4[4]), per-entity parameters a script sets through `WorldRenderer::setShaderParams` (a per-world store keyed by entity, all zero unless set), and an optional `fs_<name>_shadow.sc` replaces the engine's depth-only shader in the shadow passes and the sprite silhouette pass for that shader's draws, so a dissolving sprite loses its shadow and silhouette along with its pixels; an optional `fs_<name>_distort.sc` likewise replaces `fs_distort.sc` in the distortion pass for that shader's `distort` sprites (`CustomShaders::distortProgram`; the pass groups quads by atlas, program and parameter block and sets `u_info` and `u_params` for a game program).

**Per-frame work.** `GpuAssets::sync()` does nothing unless the asset cache's generation or its count of watched file changes moved: LUT and cooked-texture files are only looked at after the development file watcher reported a change, never in ship builds. Sprites and meshes keep their resolved sprite sheet, clip, palette textures, model, animation index and shader slot in render-side components, and particles their sheets and clips in a registry context per world, all checked against `GpuAssets::revision()` (unique across `GpuAssets` objects), so a frame looks nothing up by name per sprite, mesh or particle (the renderer places sprites through `placeSpriteClip`, the clip-resolved twin of `placeSprite`); sprite batches find materials by hash, and the canvas looks a UI image up once per run of quads that use it. A frame also allocates nothing on the heap in instance grouping, light binning, shadow selection or mesh posing (their scratch is kept between frames; a model at rest copies its baked rest pose, and a mesh entity neither in view nor in a shadow volume is skipped before it is posed), and the light and cell textures are uploaded only when their contents changed.

**Lighting.** Point and spot lights, any number up to 256 per world, are binned into a world-space XZ grid of cells. A fragment shades the lights of its own cell, up to 16 of them. Selection never happens per object, so neighbouring chunks and sprites always agree on which lights exist. When more than 16 lights reach a cell, they are ranked by unflickered intensity and falloff, so flicker can't reorder them. A light's flicker is a keyframe curve (`flicker_curve`, `[seconds, scale]` pairs that loop) times a noise wobble (`flicker`, `flicker_speed`). Spot cones need 0 ≤ `inner_cone` < `outer_cone` ≤ 90 degrees (a glTF cone with equal angles imports with a half-degree edge), and the shader never gives a cone edge zero width.

**Post-processing** (`PostPass`, per world, from the HDR scene):

- **Ambient occlusion** (`ssao`), at half resolution: twelve view-space samples around the surface reconstructed from depth, then a depth-aware blur in two passes.
- **Depth of field** at half resolution. A signed circle of confusion comes from scene depth (`focus_distance`, default the camera distance, and `aperture`), from the screen-space tilt-shift band (`focus`, `focus_range`), or the stronger of both (`dof_mode`). A 32-tap golden-angle gather keeps the near and far fields apart: the far field only gathers samples that are themselves far and wide enough to reach the pixel, so sharp foreground never smears into the blurred background, and the near field spreads over what is behind it with a coverage alpha. Bright samples weigh more, so highlights open into bokeh discs. `dof_radius` is the widest blur in screen pixels.
- **Bloom**: a mip chain of up to `bloom_levels` (default 6) halvings with a 13-tap downsample (the first level applies the soft-knee `bloom_threshold`/`bloom_knee`), then 9-tap tent upsamples that add each coarser level weighted by `bloom_radius`, normalised so the radius changes the shape, not the energy.
- **Composite**: distortion offsets, chromatic aberration (`chromatic_aberration`; the same shift as the screen pass's `chromatic`, `chromatic.sh`, but on this world's scene before tone mapping), the depth-of-field fields (the focus distance and the occlusion's field of view follow the interpolated camera, like the scene; under an orthographic camera depth is read as linear and the occlusion's samples spread by the view's height instead of its field of view), occlusion, bloom, exposure, tone mapping (`tonemap`: `"aces"` or `"none"`), sRGB encoding, two blended 3D LUTs, tint and vignette. The scene's colour is multiplied by its coverage before the near field and the bloom are added, and the output alpha is that coverage (plus the near field's), so the result is premultiplied.
- **Game post shaders** (`post.custom`, see [authoring](authoring.md#post-shaders)) in order, then **FXAA** (`antialias`: on by default unless `pixel_scale` > 1). These run on the graded, premultiplied image at output resolution, ping-ponging between two targets; FXAA filters alpha along with colour, so an edge against a transparent background fades by coverage instead of taking the clear colour of the empty pixels beside it, and the last pass blends premultiplied over the output.

`FrameMath.h` holds the CPU side of these rules (mip sizes, circle of confusion, chromatic shift, post and water uniform packing, target pooling, freeze lifetime, parameter packing, instance grouping and normals, premultiplied colours, glyph offsets, thumbnail scaling) with doctests; the shaders mirror its formulas.

**Colour.** Lighting is computed in linear space. World textures, sprite atlases, backdrops and panoramas are decoded from sRGB, and the post pass encodes the result. Environment, material and vertex colours are linear values; vertex colours above 1 make glowing geometry. The canvas keeps image, font and colour values as stored and blends in sRGB space. Palette-swap atlases are sampled undecoded, so the red channel is an exact index.

**Assets.** GPU copies are dropped only when their own CPU asset is reloaded or evicted from the asset cache (an image, sprite sheet with its normal and emissive images, model or LUT file; `GpuAssets::sync()` asks `AssetCache::loaded()` first, so an evicted asset is not decoded again just to be compared). Font pages re-upload after any reload. Model textures are shared by every model that names the same image file with the same colour space and mip setting, so a tileset ten props use uploads once, and a glTF sampler without mip filtering gets its image without a mip chain. Map and mesh textures, backdrops and panoramas load a cooked `.ktx` next to their PNG (`fengine_assetc cook`) when one exists in a format the GPU samples (not for a sampler without mips); writing, replacing or deleting the `.ktx` swaps the texture while the game runs, and only the models that use that texture re-upload. Sprites and UI images always use the PNG.

## Audio

The runtime mixes with miniaudio at 48 kHz stereo; headless runs use a silent `NullAudio` (voices never report `playing`, lengths are 0). Signal flow: sound -> bus group (`fe.audio.set_bus_volume`) -> bus effects -> `master` group -> `master` effects -> device. The buses `master`, `music`, `sfx` and `voice` always exist; any other name is created on first use.

- **Bus effects** (`fe.audio.set_bus_effect`, read back with `fe.audio.bus_effect`) run on the mixer thread: a 12 dB/octave low-pass (`lowpass` cutoff in Hz, 0 = off), a Freeverb-style reverb (`reverb` wet mix, `room`, `damping`) and ducking. New settings glide sample by sample (over `fade` seconds, at least 5 ms), so animating them every tick does not click. The `master` bus ends in a soft peak limiter (`MiniAudio::setMasterLimiter`, on by default): its gain drops within a millisecond of a peak over -0.45 dBFS and recovers over 200 ms, and what still passes is soft-clipped towards full scale, so a loud mix never hard-clips the device while quiet sound passes untouched.
- **Ducking** (`fe.audio.duck(bus, amount, {key, attack, release})`) is a sidechain: the bus drops by `amount` while the key bus (default `voice`) carries signal and recovers 50 ms after it falls silent, gliding over `attack` and `release`.
- **Music** streams. A track starts once its stream is buffered, on the same mixer frame as every other track cued in the same tick (a cue group; a slow file cued in an earlier tick never holds back tracks cued later, and a `sync` stem cued while main is still buffering joins main's group), so stems started together are sample-aligned. A stem with `sync = true` joining a main track that is already playing is buffered at main's position a moment ahead and scheduled to start exactly then; that position is read from main's cursor paired with main's own frame count, which the mixer advances in the same step, not with the engine clock, which lags them by up to a mixer period. Resuming from the global pause restarts the held sounds a margin ahead so the pairing holds afterwards. `seek_music` cues a fresh stream at the new position (seeking a playing stream would stall it while it refills); seeking or re-pitching `main` carries its synced stems along. `pitch` is varispeed by default: speed and pitch change together. With `preserve_speed` (on `fe.audio.music`, `set_music_pitch`, `sound` and `set_voice`) the sound keeps its duration and only the pitch moves: a `PitchShift` node (`engine/audio/PitchShift.h`) is put between that sound and its bus, a granular overlap-add shifter on a delay line (two raised-cosine grains half a grain apart reading at the pitch ratio, each restarting behind the write head at the offset, searched WSOLA-style within 5 ms, that best matches the other grain), which outputs one frame per input frame, so cursors and positions keep real time. It shifts 0.5 to 2; a pitch outside that falls back to varispeed, logged once. A ratio of 1 passes the signal through untouched.
- **Voices** (`fe.audio.sound`) are decoded once and cached, up to a budget (`MiniAudio::setSoundCacheBudget`, default 64 MiB of decoded f32 stereo, 384 KB per second): over it the least recently played files are dropped first, never one a voice is still playing. Files longer than the stream threshold (`setSoundStreamThreshold`, default 10 s: voice-over, ambiences) stream instead of being decoded. At most `MiniAudio::setMaxVoices` voices (default 64, fading ones included) play at once: a sound started when the cap is reached steals a voice already fading out if there is one, else the oldest non-looping voice on the lowest-priority bus (`sfx`, then game-defined buses, `voice`, `music`), and only when every voice loops a looping one; the stolen voice stops at once and no longer reports `playing`. `playing(voice)` is true until the voice ends or is stopped; `position(voice)` and `length(path)` are in seconds.
- **Global pause** (`fe.audio.set_paused(true)`) holds every sound playing at that moment; sounds started while paused play normally (menu sounds) and resuming continues the held ones. It is separate from the device suspension on focus loss.
- **Positional one-shots** (`position` and optionally `world` on `fe.audio.sound`) are heard from that world's camera (the focus world by default) with the same model as entity emitters: gain falls linearly to 0 at `radius`, pan follows the camera's right vector. They are re-placed every tick and are silent while their world is not drawn.
- **Devices**: the default output is followed when it changes (CoreAudio, WASAPI); if the device stops or disappears the mixer keeps time on the game thread, so fades and one-shots still finish, and the default device is reopened once a second.

## Library kits

Each kit is ordinary Lua, documented at the top of its file. Games change behaviour through settings tables, registries (placement types, verbs, routines, event conditions), signals and replaceable module functions, or by overriding a module. Every helper a kit's own code calls is a module function (`field.spawn_placements`, `field.make_player`, `dialogue.acquire`, `cutscene.watch`, `event.active_index`, `shop.price`, `menu.items_page`, ...), never a file-local one, so replacing one never needs a copy of the file. A kit that extends another kit's function wraps it once and keeps the wrapper in place across reloads (`fe.vehicle` wraps `field.control`, `field.update_followers` and `encounter.table_at` through `vehicle.install`). Kits load each other lazily where they are optional: the field uses encounters, saves and battles only when they come up, the starter installs the RPG kit only for games that use it, and the field watches the RPG party's `changed` signal only when that module is loaded (it never loads it). `fe.field` is split: `fe.field.placements` holds the built-in placement types and `fe.field.followers` the follower trail; both install themselves on the one `fe.field` table (`require("fe.field")` is unchanged) and a game replaces either file by path.
