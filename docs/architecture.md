# Architecture

```
game folder      main.lua · data/*.json · maps/ · sprites/ · audio/ · any Lua modules   (owned by the game)
     │ require: the game folder is searched first, so a game overrides any kit module
lualib/fe/       scene · task · signal · tween · state · save · schema · data · test
                 field · event · cutscene · dialogue · ui · rpg · effects · battle · tactical · ...
     │ sol2 bindings (fe.*), described by generated docs/api.md and lualib/types/fengine.d.lua
engine/          platform · input · assets · world · nav · render · canvas · text · audio · saves
                 Lua host · hot reload · editor · replays                         (C++ services only)
```

## The boundary rule

If a concept would appear in a JRPG design document, it does not belong in `engine/` C++. The engine knows about entities, sprites, meshes, lights, grids, paths, reachability, raycasts, text, sounds and files. It does not know about HP, parties, items, skills, battles, turns, shops, encounters or quests. `tools/ci/check_boundary.py` scans `engine/` for that vocabulary and is a CTest test.

## Libraries and programs

| Target | Contents |
| --- | --- |
| `fengine_core` | Headless: `core` (paths, JSON, asset cache, random), `assets` (images, glTF models, sprite animations), `text`, `nav`, `world`, `services` (input state, canvas command list, screen effects, audio interface, saves, platform services), `script` (Lua host and bindings), `runtime/Engine` and the headless runner |
| `fengine_runtime` | SDL3 window and input, miniaudio, bgfx renderers (world, canvas, ImGui), the editor, `MainLoop` and `ReplayHarness` |
| `fengine` | The player and development runtime |
| `fengine_headless` | `--test`, `--check` and `--write-api`; needs no GPU or display |

Game files are read through `engine/core/Paths.h`. A folder may ship as a `.pak` archive (`engine/core/Pack.h`: an index of names, sizes and CRC-32s, with each entry stored or zlib-compressed); `<dir>/game.pak` stands in for `<dir>/game` and `lualib.pak` for `lualib`. Mounting an archive lays its entries over the folder: `require`, `fe.fs`, `fe.json.read`, maps, images, sprites, fonts, glTF models, LUTs, cooked `.ktx` textures and compiled game shaders (`shaders/<backend>/*.bin`) read them in memory, and audio, which miniaudio opens by file name, is extracted on first play into a private temporary folder that is removed at exit. Where a loose file and an entry share a path, development builds read the loose file and ship builds the entry. Archive entry names are validated relative paths, and every path a script names still goes through `resolveInside`, so archives are sandboxed like folders. The asset cache also reads `user://` images (save thumbnails) from the user-data folder, read only.

Services in the core are plain data. For example, the canvas records quads and the world stores entities, lights and overlays. The runtime's renderers consume that data, so all game logic, including UI, runs and is tested headless.

## A frame

`MainLoop` pumps SDL events into `InputState` and advances logic at a fixed 60 Hz. Each tick runs, in order:

1. Background world loads advance, then input: raw input queued since the last tick is applied. Each raw input changes between up and down at most once per tick, so a tap shorter than a tick reads as pressed on one tick and released on the next. Text typed since the last tick becomes this tick's `fe.input.text()`, and the IME's latest pre-edit string becomes `fe.input.composition()`.
2. Every world's `beginTick`.
3. The entry module's `update(dt)`; `fe.game` applies its pause and time scales to the worlds, then runs the task scheduler and the scenes' `update` there.
4. Every world ticks: movement, contacts, animation, particles and the events `world:events()` returns.
5. The entry module's optional `post_update(dt)`, for logic that needs this tick's movement and events; `fe.game` runs the scenes' `post_update` and `game.post_updated` there (the field handles world events, encounters, followers and the camera in this phase).
6. Audio: looping positional sounds are updated for every world drawn on the previous frame, each heard from its own camera. Sounds of destroyed entities, unloaded worlds and worlds not drawn stop. Each drawn world's camera becomes the listener for positional one-shots of that world (see [Audio](#audio)).
7. Platform services get their per-tick update (`PlatformServices::update`).

Rendering then calls `draw(alpha)`. Scenes ask for worlds to be drawn (`world:draw()`) and draw UI on the canvas. The renderer draws the requested worlds, then the canvas, then the screen effects, then the editor and error overlay. After the frame the runtime carries out the scripts' requests: title, display changes, screenshots, text entry (IME and on-screen keyboard) and rumble.

## Lua host

- **Sandbox.** Lua 5.4 through sol2. Scripts get base, string, table, math, coroutine and utf8. `io`, `os`, `debug`, `package`, `load`, `loadstring`, `dofile`, `loadfile` and `string.dump` are absent, and `collectgarbage` only accepts `"count"` and `"step"`. The string metatable and every metatable sol2 creates are locked: `getmetatable` returns `false` and `setmetatable` refuses them. Engine objects (`World`, `Entity`, `Camera`, `RandomStream`) show scripts only their documented methods and properties (`LuaHost::sealTypes`, from the members `TypeBinder` registers): any other key reads as nil, including the metamethods and sol2 bookkeeping that sol2 keeps in the same table (`__gc`, `__index`, `__eq`, `__type`, `__name`, `class_cast`, `class_check`...) and non-string keys; assigning anything but a writable property raises an error (`World.spawn is read-only`, `Entity has no field 'speed' to assign`); iterating them with `pairs` or `next`, and `rawget` or `rawset` on them, raise errors. `==` and `tostring` work (`World(<name>)`, `Entity(<id or key>)`, and `Camera: 0x...` or `RandomStream: 0x...` for the others), and objects of different types compare unequal; error messages name these documented types, never sol2's C++ names (`bad argument #1 to 'World:spawn' (World expected, got Entity)`), and sol2 does not print errors to stderr, since every one reaches the script as a Lua error. Methods check the object they are called on, so one type's method cannot run on another type's object. The engine types are not globals, and sol2's own globals (each type's storage and the exception handler, `sol.*`) are moved into the registry after binding, so nothing a script can reach belongs to sol2. `require` searches the game folder, then `lualib/`. `fe.dev.console` (the only way to compile a string of Lua at runtime), `fe.input.feed` and `fe.input.feed_text` (which inject raw input and typed text) are bound in development builds, in `--test`, `--check` and `--write-api` runs (of `fengine_headless` and of `fengine`, which also runs them headless; these runs count as development, with the watchdog, also in a shipped `fengine`), and in `fengine --replay` and `--record` sessions, also of shipped builds. A shipped game played normally has none of them. Development builds add a watchdog that stops a frame (and, under `--test`, a test) that runs longer than 3 seconds, by raising `script watchdog: a frame ran longer than 3.0 seconds` in the script. It interrupts Lua code (a count hook checks the clock every 200000 VM instructions) and the standard library's loops that run in C without executing Lua: pattern matching (`string.find`, `match`, `gmatch`, `gsub`), plain `string.find` and `table.move` check it every 65536 steps through a small patch of the Lua library applied at configure time (`cmake/LuaPatches.cmake`). It cannot interrupt one call of an engine binding or other C code; those bound their own work instead: library strings built in a buffer (`string.rep`, `string.format`, `gsub`, `table.concat`, `string.upper`...) stop at 256 MiB with `string too large`, `table.move` moves at most 2^26 elements per call, `table.unpack` and `string.byte` are limited by Lua's stack size, path searches expand at most 200000 cells, and the sizes, counts and positions bindings accept are bounded (see Errors). Shipped builds have no watchdog, so a script that loops for ever hangs them.
- **Determinism.** String hashing uses a fixed seed and `math.random` is seeded from the run seed, so with `--seed` the iteration order of `pairs` over string and number keys, and `math.random`, repeat between runs. The order of `pairs` over a table keyed by objects (tables, functions, coroutines or engine objects such as entities) depends on memory addresses and differs between runs: keep such keys in a list, or sort them by a stable value (an id, `entity.key`), wherever the order affects the outcome. Prefer `fe.random` streams for game randomness.
- **Errors.** Lua errors never unwind through engine C++: bindings report invalid arguments (unknown enum names such as a sprite mode, text alignment or compass direction, malformed vectors, colours or seeds) as Lua errors, and `tostring` of a value whose `__tostring` fails yields a description instead of an error. Numbers are checked against what the engine stores them in: an integer argument must fit its C++ type (`math.maxinteger` passed where an `int` is stored raises instead of wrapping to -1) and a number argument must be finite and within the float range. Every component of a position, vector, rectangle or colour lies within -1000000 to 1000000 (the world bound), and sizes, counts and speeds have documented ranges (collider radius 0 to 64 and height 0 to 1000, mover and move speeds 0 to 1000, platforms at most 64 x 64, light radius at most 1000, overlays of at most 65536 cells in at most 256 overlays per world...), so no single call makes the engine loop or allocate without end; the C++ conversions of positions to grid cells and hash buckets saturate (`floorCell`) for values from elsewhere, and `world:line_of_sight` traces only the part of the line over the grid. Tags the text resolver returns resolve again, at most 4 levels deep, and more than 1 MiB of replacements for one call raise `Text tags expand too much`. Every path a script names is checked by `resolveInside`, which also refuses a NUL character (`"x.lua\0.png"` would otherwise name `x.lua`). An entity handle carries the entity's serial number, which its world never reuses, so once the entity is destroyed `e:valid()` stays false, `==` stays false and every method raises `This entity no longer exists`, even after entt hands its slot (with a wrapped 12-bit version) to a later entity; `e.key` is that serial. Recursion through C (metamethods, `pcall`, error handlers, and bindings that call back into Lua such as path cost functions, the text resolver, `fe.harness.tick` and `fe.harness.reload`) stops at Lua's limit of 200 nested C calls with a `C stack overflow` or `stack overflow` error. Sanitizer builds (`FENGINE_ENABLE_SANITIZERS`), whose stack frames are several times larger, give the main thread a 256 MiB stack (on macOS through the linker, on Linux by raising `RLIMIT_STACK` at startup) so that limit is reached before the C stack runs out.
- **No script code inside a binding.** A binding runs only the Lua it calls on purpose, so script code can never unload a world or destroy an entity under C++ that holds it. Every table a binding reads (options, settings, vectors, colours, cells, lists) is read raw through `fe::field` (`lua::field`, `lua::get`, the vector and colour helpers, `lua::elements`) and `luaToJson`: no metamethod (`__index`, `__len`, `__pairs`...) runs, and fields must be in the table itself. The entry module's functions and a module's `__reload` are looked up raw too. Every binding registered through `ModuleBinder` and `TypeBinder` runs inside a `LuaHost::BindingCall` (functions and methods also read their own arguments, so errors name documented types), which refuses once the engine is shutting down and holds the garbage collector while the binding's C++ runs, so no finalizer (`__gc`) runs in the middle of it. The Lua a binding does call — a path `cost` function, the text resolver, the console, module loading, the test harness's ticks — runs through a `LuaHost::Callout`, with the collector running, and those bindings tolerate anything it does: path searches keep the world alive and only read the grid, which no script call can reshape; the text resolver is held by a wrapper that `fe.text.resolver` never destroys, so a resolver can replace or remove itself mid-call, and its markup is parsed before the fonts are chosen. A resolver that resolves markup with tags through `fe.text` nests; more than 8 nested resolver calls, or the watchdog stopping a resolver, raise one error from the outermost `fe.text` or `fe.canvas.text` call instead of an error per level.
- **Shutdown.** The engine first marks the host as shutting down, so every binding (and `require`) raises "engine is shutting down"; it then releases its references into the Lua state (worlds, the entry module, the text resolver) and closes the state while the rest of the engine is still whole. Finalizers that run as the state closes therefore cannot load worlds, spawn entities or create new references into it. Module binding functions are owned by the host and outlive the state (sol2 finds a stored function's destructor by its C++ type's printed name, which closures can share).
- **Entry.** `main.lua` returns `{init, update, post_update, draw, file_changed, validate}`; every field is optional. `fe.game.main` and `fe.starter.main` build that table.
- **Waiting is Lua.** `fe.task` is a pure-Lua coroutine scheduler: `wait`, `wait_until`, `wait_signal`, `all`, `race`, `join`, `cancel`, `detached`, `finally` and `ensure`. Cancelling or failing a task cancels its children and runs its cleanup; children of a task that finishes normally keep running. Engine calls return immediately; scripts wait on state, signals or `world:events()`.
- **Reloading assets.** Data tables reload with validation, and a broken edit keeps the old data. Maps, images and shaders reload too. Errors show in a dev overlay with a traceback and are logged in release builds.

## Hot reload

In development builds the runtime watches the game folder and `lualib/`. When a Lua file changes, the module that was loaded from it is reloaded. This is the contract modules can rely on:

1. The file runs again, producing a fresh copy of the module. If it fails to compile or raises an error, the error is reported and the live module is left exactly as it was.
2. If the module returned a table both times, the fresh table is merged into the live one, which is the table every `require` caller already holds:
   - **Code is replaced.** Every function the module itself defined is replaced by its fresh version. A function that other code stored in the module (the game assigning `kit.on_open = ...`) is kept.
   - **Data is kept.** Non-function values the live table already has (numbers, strings, booleans, userdata, tables) keep their live value. Keys only the fresh table has are added. Keys only the live table has, such as values added at runtime or functions deleted from the source, are never removed.
   - **Nested tables merge recursively** under the same rules, including their metatables. A class table (`Class.__index = Class`) therefore stays the same table, so existing instances use the new methods. A value that is another loaded module (a `require` result) is a reference: it is never merged, and the fresh reference replaces the live one.
   - **Locals stay connected.** New functions are rewired so they see live state: an upvalue that refers to a fresh table refers to its live counterpart instead (code such as `local M = {} ... M.count = M.count + 1` updates the live `M`). Each module-level local such as `local tasks = {}`, `local now = 0` or `local box` is one variable shared by every old closure that captures it and every new function the merge reaches (the module's functions and the functions in its tables), so assigning it through any of them (`box = nil`, `tasks = {}`) is seen by all of them. Its value after the reload: local tables merge under the rules above; other live values are kept, also when the fresh copy's is nil; a live nil takes the fresh value; local functions, locals holding another module, and locals whose type changed take the fresh value, also for old closures (a function the game assigned at runtime is kept). A local only the new code captures starts with its fresh value. A name that either version uses for two different variables (shadowing in nested blocks) is not joined: the new code keeps its own variables.
3. Then, if the module has a `__reload` function (the new one), it is called as `__reload(live, fresh)`. Use it to adopt values that should change when edited (`live.speed = fresh.speed`), rebuild derived data, or re-register hooks. Its errors are reported.
4. If either version is not a table, the module cache takes the fresh value; code that already holds the old value keeps it.

Consequences for module authors:

- Top-level code runs again on every reload. Registrations made there (signals, effect hooks, input definitions, schema or data registration) must be idempotent, for example keyed by name, or move into `__reload`. `signal:connect(fn, priority, key)`, `save.add_meta(fn, key)` and `i18n.add_resolver(fn, key)` replace an earlier registration with the same key; registries (`field.define`, `field.verb`, `schema.define`, `story.define`, ...) are keyed by name. The library kits register this way, keep their state in module fields, state sections or module-level locals, and use `__reload` for edited constants (`camera.defaults`, the day/night keyframes, theme colours). `fengine_headless --test` reloads every stateful kit in the middle of a game (`lualib/tests/game/tests/reload.lua`, through `fe.harness.reload`).
- An edited constant does not apply until restart unless `__reload` copies it. Keep tunable constants as module fields, which `__reload` can copy, rather than locals, which it cannot.
- Functions created by the top-level code and handed to another module (for example `signal.connect(fn)`) are new closures that the rewiring never reaches: each local they capture is their own copy, holding the live value at reload time. Later assignments to the module's local are not seen by them, so a table such a listener reads must be mutated in place, never replaced (the kits do this: fe.field clears its entity list for a new map instead of assigning a new one, because its `state.changed` listener reads it).
- Lists merge by position, so a registry kept as a list (hook lists) can pair a live entry with a different fresh one. `fe.effects` therefore re-registers its own hooks by id in `__reload`.

The battle, RPG and effects kits follow this: their top-level registrations are keyed (effect hooks, formulas and handlers by id or name, schemas and state sections by name, i18n defaults by key), installers such as `rpg.install` run once, and the party's actor cache checks each object against the saved record instead of listening to a signal. Tests reload these modules in the middle of a battle with `fe.harness.reload`.

## World

`fe.world.load(name, map)` creates a named world, and several can exist at once (the field stays loaded while a battle stage renders). `fe.world.load_async(name, map)` does the slow parts in the background for loading screens: a worker thread parses `map.json`, then `AssetCache`'s worker decodes the map geometry, panorama, backdrops, LUTs, emitter and weather sprites and finally the sprites' atlases, while `fe.world.load_progress(ticket)` reports 0..1. `fe.world.finish_load(ticket)` builds the `World` on the main thread from the cached results. A world owns:

- **Entities.** Generational handles with a transform, sprite (directional clips, tint, flash, outline, palette swap), mesh (glTF node animation), light, emitter, mover, collider, platform, tags and a free `props` table.
- **Map grid.** Multiple layers with per-cell height, walkability, ramps (with a per-cell rise) and tags; links between layers for bridges; ladder links; points; zones; placements. C++ never interprets placements or props; `fe.field` spawns them by type.
- **Queries.** A* paths and Dijkstra reachability with step limits, blocked and no-stop cells, zones of control (cells that end movement), horizontal gap jumps (along the axes, and the diagonals with `jump.diagonal`), ladders (`ladders = false` leaves them out) and an optional Lua cost function per step; line of sight, shapes, raycasts (grid, cliff faces, map colliders, solid entity colliders and sprites; triggers only with `solid_only = false`) and mouse picking of cells and sprites. Ties between equal-cost cells break on the cell key, so paths are the same on every platform. Path and reach results mark steps that jump or climb, so presenters can animate them. An A* search expands at most 200000 cells; one that stops there before settling the goal says so (`Route::truncated`, `truncated = true` on the Lua list) instead of passing off a partial result as the cheapest route. A mover never follows such a route: `move_to` stops and emits `blocked`, as when no path exists.
- **Movement.** Movers walk, jump and climb to targets or along given routes (`move_to(nil, {path = cells})` follows a reach path in one call, carrying leftover distance from waypoint to waypoint), colliding against the grid and other solid entities through a spatial hash. Path finding and movers change layers through one shared rule (`Grid::traverseLink`) and take ladders through another (`Grid::ladderStep`), so every planned path is walkable. Platforms (moving surfaces) carry movers and colliders standing on them and make the cells they cover walkable at their height. The resulting events are delivered through `world:events()`: `contact_begin`, `contact_end`, `arrived`, `blocked`, `jump_start`, `landed`, `climb_start`, `climb_end`, `anim_event`, `anim_finished`, `zone_enter` and `zone_exit`. Events naming an entity destroyed before they are read are dropped, so no event arrives with `a` or `b` missing: a contact with something destroyed in the same tick is never delivered, and destroying an entity ends its contacts without a `contact_end`.
- **Presentation.** Environment (ambient, sun, fog, shadows, water, sky gradient and backdrops, weather, post-processing with two blended LUTs, bloom, tilt-shift, tone mapping, pixelation), particles, tile overlays with pulse, path arrows and a cursor, and a camera.

`World` owns the registry and hands it to its systems, one file each in `engine/world/`: `Movement` (movers, routes, jumps, ladder climbs, platforms, attachments, link switching), `Collision` (static boxes, the spatial hash, ray tests, contacts and zones), `Animation` (sprite and mesh clips, frame events, sprite quads for picking), `Particles` (emitters, bursts and weather) and `Overlays` (cells, path arrows, cursor), plus `Camera`. Each tick runs them in that order: platform riders are noted, movement, platforms carry their riders and move their grid overrides, attachments, animation, particles, contacts, zones.

- **Platforms.** An entity with a `platform` component is a moving surface whose top is its position and whose footprint is `size`. Riders (movers and colliders on its top, not jumping, climbing or attached) move with it each tick; riders that collide when walking are still stopped by solid entities that are not aboard (sliding along them where one axis is free) and left behind. Grid cells whose centre it covers on its layer are rewritten as walkable at its height, and restored when it moves on, unless a script changed them in between. Move platforms with `mover{collide = false}` or `place`.
- **Static data.** Map colliders (plus geometry marker boxes) and map emitters are turned into collision boxes and emitter entities by `World::rebuildStatic()`, at load and after every editor edit; lights are read from the map each frame.

- **Pause and time scale.** `world.paused` stops a world's tick (it still renders and scripts can still change it); `world.time_scale` multiplies its tick length (slow motion, hit-stop, fast-forward; 0 to 10, since longer steps would let movers pass through walls). The engine applies both when it ticks worlds.
- **Spatial hash.** Colliders enter and leave the hash as the components are added or removed, and spawn, `place` and movement keep it current, so `can_occupy` is exact during the script update. Queries reach out by the largest collider radius, which follows collider construction and updates; C++ that changes a collider's radius does it through `registry.patch` or `replace` (the Lua bindings do), so a collider grown by a script blocks at once. Inside a link cell, standing room counts the other surface of every link of the cell, as `Grid::traverseLink` does.
- **Events.** Events wait in a queue until `world:events()` reads them. The queue keeps at most 4096; when nobody reads it, the oldest are dropped with one warning per overflow.
- **Zones** report entities with a transform and a mover or collider. Scenery without either never triggers zones.
- **Weather** kinds are data: `@fe/assets/weather.json` holds the emitter settings per kind (`rain`, `snow`, `leaves`, `embers`, `dust`, `custom`) and a game's `data/weather.json` adds or replaces kinds.
- **Particles** are stored in world space. Emitters with `world_space = false` keep their particles' offsets from the emitter and move them with it; `max` caps the live particles per emitter. The particle system counts each emitter's live particles itself, so giving an emitter new settings keeps the cap of the particles it already has alive.
- **Animation clips** are always looked up through `SpriteAnimation::clip()`: an unknown clip name shows, fires the frame events of and finishes (`anim_finished` with the requested name) like the clip it falls back to, `idle` or else the first clip.
- **Light flicker** noise is seeded per light, map lights by their position (a hash of it, so lights authored at the same position flicker together and moving one changes its phase) and entity lights by their entity, so adding, removing or reordering lights never changes another's phase.

## Platform

The core has no window or devices; it records what scripts ask for and what the runtime reports, so everything below also runs headless.

- **Display.** `Engine::display()` is the window and monitor state (`engine/platform/Display.h`): fullscreen mode (window, borderless or exclusive), window size, vsync mode, monitor and the monitors' exclusive modes. `fe.app.set_display` validates a change, queues it in `AppRequests` and shows it in `fe.app.display()` at once; after the frame the runtime moves, resizes or switches the window (`Window::apply`), sets the renderer's vsync and reads the real state back. Adaptive vsync is the runtime's `AdaptiveVsync`: it presents in sync while frames keep up with the monitor's refresh rate and stops waiting for vertical blank when they fall behind. Headless runs report one monitor the size of `game.json`'s window. The engine does not persist display settings; `fe.config` does.
- **Text entry.** `fe.input.text_begin(rect, kind)` and `text_end` are requests on `InputState`; `SdlInput::apply` starts SDL text input with the kind (`text`, `name`, `number`) and the IME candidate area converted from canvas to window coordinates. SDL opens an on-screen keyboard where the system has one, including Steam Deck's. Committed text and pre-edit strings come back as SDL events and are queued like other input, and `--record` writes both into the replay. Pre-edit strings count only while the game's text entry is active, so events still queued when `text_end` runs don't bring a composition back, and losing window focus ends the composition.
- **Gamepads.** `SdlInput` describes every connected gamepad to `InputState`: number, name, layout (`xbox`, `playstation`, `switch`, `steamdeck` from the Deck's own controls, or `generic`) and rumble capabilities. `fe.input.device_type()` follows the device used last, for button prompts. Rumble requests (handle and trigger motors) are played after the frame and stopped when the window loses focus.
- **Locale.** The runtime passes SDL's preferred locale to the engine as a BCP 47 tag (`fe.app.locale()`); headless runs, replays and recordings use `en-US` so they don't depend on the machine.
- **Platform services.** `PlatformServices` (`engine/services/PlatformServices.h`) is the store interface behind `fe.platform`: unlocks and stats, plus a per-tick `update`. `LocalPlatformServices`, the default, keeps them in `<user data>/platform.json`. A port supplies its own through `EngineOptions::platform` or `RuntimeOptions::platform`.
- **Library lookup.** `findLibraryRoot` looks for `lualib/` next to the executable (`<exe dir>/lualib`, an app bundle's `Resources/lualib`, `<exe dir>/share/fengine/lualib`). Development builds also search the folders above the executable and fall back to the source tree; shipped builds (`FENGINE_DEV` off) look nowhere else.

## Text

`engine/text` parses markup into units (characters, icons and timing marks; typewriter effects count them), lays them out and paginates them; the canvas turns layouts into quads. Fonts are named sets of faces (bitmap `.fnt` and TrueType), with fallbacks scaled onto the primary face's baseline and pair kerning; a font `<name>.bold` (or `bold` in `fe.text.font`) is the `{b}` face, otherwise bold glyphs are drawn twice, 1px apart.

- **Markup.** `{color}`, `{icon}`, `{wait}`, `{speed}` (`{speed:0}` = instant), `{size}`, `{b}`, `{shake}`/`{wave}` and `{ruby:base|reading}`; other tags go to the script resolver. Pagination writes pages back as markup, so every tag survives it.
- **Lines.** Lines break at spaces and between CJK characters, following kinsoku rules: no line starts with closing punctuation, small kana or the prolonged sound mark, and none ends with an opening bracket (the character before moves down instead). A ruby base never breaks; a line is as tall as its largest glyph plus room for its readings, which sit centred above their base at half size and appear with it. A reading wider than its base spreads the base instead of overhanging it: the extra width goes half a share before the first base character, a share between characters and half a share after the last, as Japanese typesetting does.
- **Effects.** Laid-out glyphs and their canvas quads carry `effect` (shake or wave) and `phase` (the unit index); the canvas renderer moves them.
- **Scripts.** Right-to-left scripts (Arabic, Hebrew) are not supported: there is no bidirectional reordering or shaping.

## Rendering

`FrameRenderer` draws each frame in this order:

1. **Worlds**, in `world:draw()` order. Each world renders its 3D scene into an off-screen HDR target, then post-processes it over its output with the scene's alpha. A later world draws on top of an earlier one. Where a world has no sky (`sky.mode = "none"`) and no geometry, the background stays transparent, so the worlds drawn before it show through. A draw goes to the whole screen, to a screen `rect` (picture-in-picture), or into a named render **target** that `fe.canvas.image("rt:<name>")` shows (minimaps, 3D portraits; a target holds premultiplied colour, so the canvas blends it premultiplied, its colour premultiplied too); its optional `camera` replaces the world's camera for that draw only, so one world can be drawn several times per frame, and its optional `post` replaces fields of the environment's post-processing for that draw (a minimap without depth of field or bloom). A draw camera is interpolated like the world camera: `FrameRenderer` keeps, per world, target and order of such draws, the values of the previous tick and blends towards the current ones with the frame's alpha (`DrawCameras` in `FrameMath.h`); a draw missing for a frame starts snapped. Scene, post and render targets are pooled by size (or name) and released after a frame that didn't use them. The number of draws per frame is limited by bgfx's view count: 24 views for the scene (16 of them light-shadow tiles) plus 4 to about 30 for its post-processing, depending on its settings.
2. **Scene captures** (`fe.save.thumbnail`): the frame so far, worlds only, is copied to a read-back texture. Once the GPU has read it back (a frame or two later) it is box-filtered to at most 480 pixels across and written as PNG through a temporary file.
3. **The canvas UI**, composed in sRGB space. Glyph quads with an effect (shake, wave) move by whole canvas pixels at draw time.
4. **The screen pass**, which applies `fe.screen` to everything, UI included, while copying to the back buffer: the freeze-frame, letterbox, transition (`fade`, `swirl`, `mosaic`, `wipe`, `iris`, `shatter`), radial blur, chromatic aberration (one rule with the post pass's: with amount a, red is read a × 3% further from the screen centre and blue as much nearer), fade and flash. It runs with no world drawn too. `tint` multiplies only the 3D scenes. `fe.screen.freeze()` copies the frame that is on screen (last frame's worlds and canvas, before screen effects) into a texture that the screen pass shows instead of the live frame, which keeps rendering underneath; a transition then goes from the held image to the live one instead of to its colour, which is how battle intros swirl or shatter the field into the battle. `fe.screen.unfreeze()` releases it.
5. The editor and the error overlay (ImGui).

Each world's scene, in `WorldRenderer`:

1. **Sun shadows.** Three cascades are fitted to the camera frustum, without screen shake, out to `shadow_distance` past the camera focus. Each cascade box surrounds a bounding sphere of its frustum slice and is snapped to whole shadow texels, so shadows don't shimmer while the camera moves. Casters are culled per cascade. `shadow_strength` and `shadow_bias` are environment data.
2. **Light shadows.** Point and spot lights with `shadows` (`castShadows`) render depth into one shared atlas of 16 tiles of 512×512: a spot light takes one tile (its cone), a point light six (a cube). Each frame the lights in view are ranked by unflickered brightness falling off with distance from the camera focus, and tiles go to the best ones that still fit, so at most 16 spot lights, or two point lights and four spot lights, cast shadows per world; the rest light without shadows. Map chunks, meshes and opaque sprites cast (sprites with their camera-facing quad, so a light level with a sprite sees it edge-on); blended sprites and mesh parts, including opaque sprites faded by a tint alpha below 1, cast nothing rather than a full cutout. Everything lit receives them, sprites per pixel. Lookups are biased along the normal and towards the light by about one shadow texel and filtered with four hardware comparisons.
3. **Sky** (colour, gradient with clouds, or panorama) and backdrop cards.
4. **Map geometry**, baked into world-space indexed 8×8-unit chunks (each chunk remaps only the vertices it uses), then **mesh entities** with glTF node animation. Both are frustum-culled by their transformed bounds, and normals use the inverse-transpose matrix. Opaque mesh parts drawn more than once in a view (the same model part and shader) go out as one instanced draw, in the main pass and in every shadow view (`vs_world_instanced`, `vs_shadow_instanced`: the instance data is the model matrix and the tint, and the normal matrix is the cofactor matrix over the determinant); single parts draw as before. glTF sampler wrap and filter modes are honoured, textures have mip chains, and anisotropic filtering follows the environment's `anisotropic` setting. Materials use the base colour, normal map (with its `scale`; per-vertex tangents come from the file or are generated from the UVs, area weighted and smoothed across shared vertices) and emissive texture times `emissiveFactor` and `KHR_materials_emissive_strength`; emissive light is added unlit, so values above 1 bloom.
5. **Sprites and particles**, batched. Every quad goes into one per-frame vertex buffer, and consecutive quads with the same textures, shader and blend mode are drawn together. Sprites are lit at a probe `sprite_light_height` above their feet and support flash, outline and palette swap. A sprite sheet may add a normal map and an emissive mask laid out like its atlas (`normal`, `emissive` in the `.anim.json`): normal-mapped sprites are lit per pixel by the sun and point and spot lights, so lights move across them; the mask's colour is added unlit. Sprites with a `silhouette` colour first draw that colour where map geometry or meshes hide them, so characters stay visible behind walls; sprites in front still cover it. `mode = "decal"` lays a sprite on the grid surface of its layer: it is cut at cell borders and each piece follows that cell's height and ramp (`flat` stays one quad at the feet's height). With `environment.pixel_snap` (or a sprite's own `pixel_snap`) a sprite's anchor moves to the centre of a whole scene pixel every frame, so pixel art moving under the low-FOV camera doesn't shimmer. Particles use the frames of their sprite's `idle` clip (or its first clip) over their age, honour `unlit`, and are sorted with the other transparent draws. They fade out as they come nearer the camera than 30% of its distance to the focus and vanish at 10%, so weather that drifts past the lens (falling leaves spawn at about camera height) doesn't cover the screen as a blurred, blooming blob.
6. **Grid overlays**, path arrows (a strip with an arrow head) and the cursor.
7. **Blended draws**: mesh parts, water, sprites and particles whose blend mode is not `opaque`. They don't write depth and are drawn in passes: `alpha` and `premultiplied` sorted back to front, then `multiply`, then `additive`. Fog fades additive glow and multiply darkening instead of tinting them. Sprites default to `opaque` (an alpha cutout that writes depth; a tint alpha below 1 makes them `alpha`), particles to `alpha`, and mesh parts to their glTF alpha mode unless the mesh sets `blend`.
8. **Water.** Before the first water surface, `SceneTarget::copyOpaque` copies the opaque scene's colour and depth (`colorCopy`, `depthCopy`; any pass that needs the scene behind it can use them). Water then refracts the copied scene through its waves (`water.refraction`, ignoring what stands in front of the surface), tends to `water.deep_color` with the depth behind it, reflects the copied scene by marching the reflected ray through the copied depth (`water.reflection`; misses show the sky's horizon colour) and adds fresnel and sun specular. Screen-space reflection only shows what is on screen.
9. **Distortion.** Sprites and particles with `distort` draw no colour; they add screen offsets into an RG16F buffer, tested against the scene depth (so walls in front hide them): the alpha gradient of their image bends like a lens (a ring makes a shock wave) and an animated wobble makes heat haze. The post pass offsets its scene lookups by it, clamped to 3% of the screen.

**Game shaders.** A mesh material (glTF material extras or node custom property `shader`, or the mesh component's `shader` for every part) or a sprite (`shader`) can replace the engine's fragment shader with the game's `shaders/fs_<name>.sc` ([authoring](authoring.md#game-shaders)). `CustomShaders` (owned by `FrameRenderer`, shared with the post pass) compiles and loads them like post shaders and pairs each with the engine vertex shader it draws with; draws resolve names to stable slots once and cache them, and a shader that cannot be compiled, loaded or paired is reported once and the engine's own is used.

**Per-frame work.** `GpuAssets::sync()` does nothing unless the asset cache's generation or its count of watched file changes moved: LUT and cooked-texture files are only looked at after the development file watcher reported a change, never in ship builds. Sprites and meshes keep their resolved sprite sheet, palette textures, model and shader slot in render-side components, and particles their sheets and clips in a registry context per world, all checked against `GpuAssets::revision()` (unique across `GpuAssets` objects), so a frame looks nothing up by name per sprite, mesh or particle; sprite batches find materials by hash.

**Lighting.** Point and spot lights, any number up to 256 per world, are binned into a world-space XZ grid of cells. A fragment shades the lights of its own cell, up to 16 of them. Selection never happens per object, so neighbouring chunks and sprites always agree on which lights exist. When more than 16 lights reach a cell, they are ranked by unflickered intensity and falloff, so flicker can't reorder them. A light's flicker is a keyframe curve (`flicker_curve`, `[seconds, scale]` pairs that loop) times a noise wobble (`flicker`, `flicker_speed`). Spot cones need 0 ≤ `inner_cone` < `outer_cone` ≤ 90 degrees (a glTF cone with equal angles imports with a half-degree edge), and the shader never gives a cone edge zero width.

**Post-processing** (`PostPass`, per world, from the HDR scene):

- **Ambient occlusion** (`ssao`), at half resolution: twelve view-space samples around the surface reconstructed from depth, then a depth-aware blur in two passes.
- **Depth of field** at half resolution. A signed circle of confusion comes from scene depth (`focus_distance`, default the camera distance, and `aperture`), from the screen-space tilt-shift band (`focus`, `focus_range`), or the stronger of both (`dof_mode`). A 32-tap golden-angle gather keeps the near and far fields apart: the far field only gathers samples that are themselves far and wide enough to reach the pixel, so sharp foreground never smears into the blurred background, and the near field spreads over what is behind it with a coverage alpha. Bright samples weigh more, so highlights open into bokeh discs. `dof_radius` is the widest blur in screen pixels.
- **Bloom**: a mip chain of up to `bloom_levels` (default 6) halvings with a 13-tap downsample (the first level applies the soft-knee `bloom_threshold`/`bloom_knee`), then 9-tap tent upsamples that add each coarser level weighted by `bloom_radius`, normalised so the radius changes the shape, not the energy.
- **Composite**: distortion offsets, chromatic aberration (`chromatic_aberration`; the same shift as the screen pass's `chromatic`, `chromatic.sh`, but on this world's scene before tone mapping), the depth-of-field fields, occlusion, bloom, exposure, tone mapping (`tonemap`: `"aces"` or `"none"`), sRGB encoding, two blended 3D LUTs, tint and vignette.
- **Game post shaders** (`post.custom`, see [authoring](authoring.md#post-shaders)) in order, then **FXAA** (`antialias`: on by default unless `pixel_scale` > 1). These run on the graded image at output resolution, ping-ponging between two targets; the last pass blends over the output.

`FrameMath.h` holds the CPU side of these rules (mip sizes, circle of confusion, chromatic shift, post and water uniform packing, target pooling, freeze lifetime, parameter packing, instance grouping and normals, premultiplied colours, glyph offsets, thumbnail scaling) with doctests; the shaders mirror its formulas.

**Colour.** Lighting is computed in linear space. World textures, sprite atlases, backdrops and panoramas are decoded from sRGB, and the post pass encodes the result. Environment, material and vertex colours are linear values; vertex colours above 1 make glowing geometry. The canvas keeps image, font and colour values as stored and blends in sRGB space. Palette-swap atlases are sampled undecoded, so the red channel is an exact index.

**Assets.** GPU copies are dropped only when their own CPU asset is reloaded (an image, sprite sheet with its normal and emissive images, model or LUT file). Font pages re-upload after any reload. Map and mesh textures, backdrops and panoramas load a cooked `.ktx` next to their PNG (`fengine_assetc cook`) when one exists in a format the GPU samples; writing, replacing or deleting the `.ktx` swaps the texture while the game runs. Sprites and UI images always use the PNG.

## Audio

The runtime mixes with miniaudio at 48 kHz stereo; headless runs use a silent `NullAudio` (voices never report `playing`, lengths are 0). Signal flow: sound -> bus group (`fe.audio.set_bus_volume`) -> bus effects -> `master` group -> `master` effects -> device. The buses `master`, `music`, `sfx` and `voice` always exist; any other name is created on first use.

- **Bus effects** (`fe.audio.set_bus_effect`, read back with `fe.audio.bus_effect`) run on the mixer thread: a 12 dB/octave low-pass (`lowpass` cutoff in Hz, 0 = off), a Freeverb-style reverb (`reverb` wet mix, `room`, `damping`) and ducking. New settings glide sample by sample (over `fade` seconds, at least 5 ms), so animating them every tick does not click.
- **Ducking** (`fe.audio.duck(bus, amount, {key, attack, release})`) is a sidechain: the bus drops by `amount` while the key bus (default `voice`) carries signal and recovers 50 ms after it falls silent, gliding over `attack` and `release`.
- **Music** streams. A track starts once its stream is buffered, on the same mixer frame as every other track cued in the same tick, so stems started together are sample-aligned. A stem with `sync = true` joining a main track that is already playing is buffered at main's position a moment ahead and scheduled to start exactly then. `seek_music` cues a fresh stream at the new position (seeking a playing stream would stall it while it refills); seeking or re-pitching `main` carries its synced stems along. `pitch` is varispeed: speed and pitch change together.
- **Voices** (`fe.audio.sound`) are decoded once and cached. `playing(voice)` is true until the voice ends or is stopped; `position(voice)` and `length(path)` are in seconds.
- **Global pause** (`fe.audio.set_paused(true)`) holds every sound playing at that moment; sounds started while paused play normally (menu sounds) and resuming continues the held ones. It is separate from the device suspension on focus loss.
- **Positional one-shots** (`position` and optionally `world` on `fe.audio.sound`) are heard from that world's camera (the focus world by default) with the same model as entity emitters: gain falls linearly to 0 at `radius`, pan follows the camera's right vector. They are re-placed every tick and are silent while their world is not drawn.
- **Devices**: the default output is followed when it changes (CoreAudio, WASAPI); if the device stops or disappears the mixer keeps time on the game thread, so fades and one-shots still finish, and the default device is reopened once a second.

## Library kits

Each kit is ordinary Lua, documented at the top of its file. Games change behaviour through settings tables, registries (placement types, verbs, routines, event conditions), signals and replaceable module functions, or by overriding a module. Kits load each other lazily where they are optional: the field uses encounters, saves and battles only when they come up, and the starter installs the RPG kit only for games that use it.

| Kit | Purpose |
| --- | --- |
| `fe.game`, `fe.starter` | Entry loop, title, new game, continue, standard setup |
| `fe.scene`, `fe.task`, `fe.signal`, `fe.tween`, `fe.timeline` | Scene stack, coroutines, events, animation |
| `fe.state`, `fe.save`, `fe.config` | Flags and variables, save slots with metadata and migrations, player settings |
| `fe.schema`, `fe.data`, `fe.i18n` | Validated data tables (which also drive the editor's forms), localisation |
| `fe.field`, `fe.event`, `fe.cutscene`, `fe.dialogue`, `fe.camera` | Exploration, event pages and triggers, scripted scenes (fast-forward, skip), message boxes (voice-over, lip-flap, auto-advance), camera rigs |
| `fe.follower`, `fe.story` | NPC followers with battle assists; protagonists, chapters and chapter select |
